如何在网页中使用 LiveKit 和 Synthesia Avatar 并通过网页点餐（版本 6）——英语？

林邦源博士 · AI 笔记 · 2026 年 11 月 6 日 · 约 9 分钟阅读

在早前的一篇笔记中，餐厅接待员 Lin 搬进了一个 真正的网页。她只有一个工具 show_section，也只有一项任务：回答一个问题， 然后把页面滚动到她正在讲述的部分。

这篇笔记给她一份真正的工作。页面不再是三个部分加一段视频，而是一整个餐厅网站， 有菜单、酒单、价格、过敏原和账单。Lin 成为领班，她一道菜一道菜地 接受你的点单：前菜、头盘、主菜、甜点，然后是酒。她仍然会说话；现在她还会一边说话 一边在页面上行动 — 把你不能吃的菜变灰，打开她正在介绍的菜品卡片， 并把你选的东西加到角落里那张不断更新的账单上。

回答问题与接受点单：一眼看清

版本 3（回答问题）版本 6（接受点餐）
页面一页、三个部分，数字人在角落完整的餐厅网站：菜单、酒、用餐空间、实时账单
Lin 能调用的工具1 个 — show_section4 个 — show_section、filter_menu、focus_dish、add_to_order
她知道的内容FAQs.txt 里的 4 组问答13 条 — 整份菜单、价格、饮食需求、过敏原和酒
对话回答，然后停下有引导：一次一道菜、两个选项，最后是酒
页面的反应方式滚动并高亮滚动、把菜变灰、打开菜品卡片、加入账单
折扣无每道菜各点一款时，餐费九折
耳朵Cartesia ink-2相同，另加一份要留意的菜单词汇表
声音Cartesia sonic-3.6，声音 Skylar相同
网页文件所有内容都放在 index.html 里index.html（很小）+ site.js + site.css

开始之前你需要什么

  • 早前版本需要的一切 — 完整清单见如何在网页中使用 LiveKit 和 Synthesia Avatar（版本 3）？。
  • 不需要新的账户、密钥或安装包。语音、声音和面孔仍是版本 3 的那三项服务。

在自己的电脑上运行

下载 zip 文件 并解压到一个文件夹。zip 内有 agent.py、server.py、 index.html、site.js、site.css、FAQs.txt、 pyproject.toml 和 README.md。和之前一样，加入你自己的 .env 文件，写入同样的五个密钥。

第 1 步：设置项目文件夹

如果你已经有早前的某个文件夹，保留 server.py、pyproject.toml 和 .env，替换 agent.py、index.html 和 FAQs.txt，并加入两个新文件 site.js 和 site.css。 在 server.py 里你还需要两条额外的路由，因为页面现在会请求这两个文件 （第 4 步会展示）。

.env 文件完全不用改：同样的 LiveKit 密钥、Synthesia 密钥和数字人 ID。

第 2 步：看看 agent.py — 改了什么

四处改动：新增三个工具，提示词变成领班的服务脚本，耳朵拿到一份菜单词汇表， 还有一个小助手函数负责发送所有工具消息。

改动 1：一个助手，四个工具

async def _ui(self, **message) -> str:
    """Send a tiny message to the browser. step09/site.js does the rest."""
    await self.room.local_participant.publish_data(json.dumps(message), topic="ui")
    return "Done."

@function_tool
async def show_section(self, section: str) -> str:
    """Scroll the page to a part of the menu and highlight it.

    Args:
        section: One of: meal, openers, first, mains, desserts, wine, room.
    """
    return await self._ui(action="show_section", section=section)

@function_tool
async def filter_menu(self, diet: str) -> str:
    """Grey out every dish on the page the guest cannot eat.

    Args:
        diet: One of: none, vegetarian, vegan, pescatarian, nut_free.
    """
    return await self._ui(action="filter_menu", diet=diet)

@function_tool
async def focus_dish(self, dish: str) -> str:
    """Open the detail card for one dish: kitchen note and allergens.

    Args:
        dish: A dish ID from the menu, for example salmon or tofu.
    """
    return await self._ui(action="focus_dish", dish=dish)

版本 3 在它唯一的工具里手工拼出 JSON。有四个工具的话，同样的两行就会被复制四遍， 所以一个很小的私有助手 _ui 把它一次做完：它把你传入的内容转成 JSON， 并在 "ui" 数据频道上发布。于是每个工具只剩一行，而它的文档字符串 — 模型真正会读的部分 — 说明这个工具接受什么。

注意这里不再有的东西：SECTIONS 检查。版本 3 会拒绝未知的部分 名称。现在页面自己会忽略它不认识的名称，所以代理可以保持简单；唯一仍然做校验的 地方是点单，因为一道不存在的菜绝不能出现在账单上。

改动 2：接受点单

@function_tool
async def add_to_order(self, dish: str) -> str:
    """Add a dish or a glass of wine to the guest's order, shown as a running tab on the page.

    Args:
        dish: A dish ID from the menu, or a wine ID: red, white or alcoholfree.
    """
    # Accept "red", "Red Wine" or "alcohol-free" alike, the same way site.js does.
    dish = re.sub(r"[^a-z]", "", dish.lower()).removeprefix("the").replace("wine", "")
    if dish not in ORDER_IDS:  # tell the model, so it retries with a real ID
        return f"Not added: {dish!r} is not an ID. Use one of: {', '.join(sorted(ORDER_IDS))}."
    await self._ui(action="add_to_order", dish=dish)
    # Remind the model to move the page along with the conversation.
    section = next(c for c, dishes in COURSES.items() if dish in dishes)
    if section in NEXT_SECTION:
        nxt = NEXT_SECTION[section]
        return f"Added {dish} to the order. When you introduce the next part, call show_section(\"{nxt}\") too."
    return f"Added {dish} to the order."

有两个想法值得抄进你自己的代理。第一是那行清理代码：模型可能传来 "Red Wine"、"red" 或 "alcohol-free"，客人也可能 说“the red”；去掉所有非字母的字符，再去掉“the”和“wine”，它们都会变成页面使用的 同一个 ID。第二，回复本身就是一次推动。工具结果不只是收据：通过返回 “当你介绍下一部分时，也调用 show_section("mains")”，代理会悄悄把自己引导到 让页面和对话保持同步。

菜名列表本身放在类上方，紧挨着它们所属的提示词： 

COURSES = {
    "openers": ["oysters", "bread", "salad"],
    "first": ["soup", "prawns", "dumplings"],
    "mains": ["salmon", "beef", "chicken", "pork", "tofu"],
    "desserts": ["cheesecake", "chocolate", "sorbet"],
    "wine": ["red", "white", "alcoholfree"],
}
ORDER_IDS = {dish for dishes in COURSES.values() for dish in dishes}
NEXT_SECTION = dict(zip(COURSES, list(COURSES)[1:]))  # openers -> first -> mains -> desserts -> wine

COURSES 必须与 site.js 中的 MENU 和 WINES 一致。如果你在那里加了一道菜，也要在这里加上，否则 Lin 会礼貌地 拒绝为你点它。

改动 3：提示词变成一份脚本

版本 3 的提示词是一本规则手册：从常见问题里找答案，某个问题就滚动到某个部分。 版本 6 的提示词是一份职位描述。事实搬出去了 — 价格、饮食需求 和过敏原现在都在 FAQs.txt 里 — 提示词只说明该怎么表现，以及各个 工具接受哪些 ID。正是这一部分让演示像一个餐厅，而不是一个聊天机器人： 

Work like a real head waiter. Take the guest through the courses in order:
openers, then first, then mains, then desserts, asking about one course at a time.
Offer two options rather than ten. If they skip a course, let them, but mention
once that one dish from each course gets 10% off. After desserts, offer a glass of
wine once, and let the guest pick any one; if they say no, that is fine. Do not
suggest a wine for a particular dish.

小规则，大效果。“两个选项而不是十个”让口头回答保持简短。“一次一道菜”给对话一个 形状，也让 show_section 在每一轮都有事可做。“不要为某道菜推荐搭配的酒” 阻止模型编造它不可能知道的搭配。

还有一段新的关于听错的词的说明，它是整个文件里最实用的一行： 

What the guest says reaches you through speech-to-text, which sometimes mishears.
If their words make no sense, they are probably not a question: think what they
most likely said, given what you just asked. For example, right after you offer
wine, "wet why" is probably "red wine" or "white wine". Check with them in a few
words, such as "Red wine, is that right?", or ask them to say it again. Do not use
the "Any other question?" answer for words you did not understand.

没有它，一个听错的菜名会把 Lin 送进兜底回答，听起来就像机器人放弃了。有了它， 她会改问一个简短的问题 — 正是服务员会做的事。

改动 4：耳朵拿到一份词汇表

# Words the speech-to-text should listen out for, so "red wine" is not heard as "wet why".
KEYTERMS = [
    "YouFantasy", "Oysters", "Garlic Bread", "Green Salad", "Tomato Soup", "Grilled Prawns",
    "Vegetable Dumplings", "Salmon", "Beef", "Roast Chicken", "Pork Belly", "Crispy Tofu",
    "Cheesecake", "Chocolate Cake", "Mango Sorbet", "Red Wine", "White Wine", "Alcohol-Free",
    "openers", "first course", "mains", "desserts", "vegetarian", "vegan", "nut free",
]
stt=inference.STT(model="cartesia/ink-2", extra_kwargs={"keyterm": KEYTERMS}),  # speech -> text

这些词作为 keyterms 传给语音识别器：是提示，不是规则。餐厅名、菜名 和饮食相关的词，正是通用模型容易听错的那一类；而菜名听错比形容词听错更糟 — 它会进账单。流水线的其余部分与版本 3 相同：openai/gpt-4.1-mini 当大脑， cartesia/sonic-3.6 配 Skylar 的声音，轮次检测设为 "stt"， 以及同一个 Synthesia 数字人，带着三次尝试的冷启动重试。

第 3 步：完整的 agent.py

这里是完整文件，让你看到四处改动在上下文中的样子： 

"""Version 6 (English): the full restaurant. Lin is a head waiter who takes the guest's whole order.

The pipeline:
    mic -> VAD -> STT -> turn detection -> LLM (+ tools) -> TTS -> Synthesia avatar -> browser

New in this version: the page is a whole restaurant website (site.js + site.css) and Lin has
four tools instead of one - show_section, filter_menu, focus_dish and add_to_order - so she
can grey out dishes for an allergy, open a dish card and keep a running tab. The prompt turns
her into a head waiter who guides the guest through four courses, and the speech-to-text gets
a list of menu words so "red wine" is not heard as "wet why".

Run:  uv run agent.py dev    (terminal 1)
      uv run server.py       (terminal 2, then open http://localhost:8080)
"""

import asyncio
import json
import os
import re
from pathlib import Path

from dotenv import load_dotenv
from livekit.agents import Agent, AgentSession, JobContext, WorkerOptions, cli, function_tool, inference
from livekit.plugins import silero, synthesia

load_dotenv(dotenv_path=Path(__file__).parent / ".env")

AGENT_NAME = "avatar-demo"  # must match server.py
AVATAR_ID = os.getenv("SYNTHESIA_AVATAR_ID") or "8788bef1-8020-46e0-a8f4-510ea9989b25"  # Jenny
VOICE_ID = "db6b0ed5-d5d3-463d-ae85-518a07d3c2b4"  # Cartesia "Skylar"

# Everything add_to_order accepts, by page section, in the order Lin takes the guest
# through them. Must match MENU and WINES in step09/site.js.
COURSES = {
    "openers": ["oysters", "bread", "salad"],
    "first": ["soup", "prawns", "dumplings"],
    "mains": ["salmon", "beef", "chicken", "pork", "tofu"],
    "desserts": ["cheesecake", "chocolate", "sorbet"],
    "wine": ["red", "white", "alcoholfree"],
}
ORDER_IDS = {dish for dishes in COURSES.values() for dish in dishes}
NEXT_SECTION = dict(zip(COURSES, list(COURSES)[1:]))  # openers -> first -> mains -> desserts -> wine

# Words the speech-to-text should listen out for, so "red wine" is not heard as "wet why".
KEYTERMS = [
    "YouFantasy", "Oysters", "Garlic Bread", "Green Salad", "Tomato Soup", "Grilled Prawns",
    "Vegetable Dumplings", "Salmon", "Beef", "Roast Chicken", "Pork Belly", "Crispy Tofu",
    "Cheesecake", "Chocolate Cake", "Mango Sorbet", "Red Wine", "White Wine", "Alcohol-Free",
    "openers", "first course", "mains", "desserts", "vegetarian", "vegan", "nut free",
]

FAQS_FILE = Path(__file__).parent / "FAQs.txt"  # the avatar's knowledge

# {faqs} is replaced with the contents of FAQs.txt at the start of every call.
# The facts (prices, diets, allergens, wine) live in FAQs.txt; this prompt only says
# how to behave and which IDs the tools take.
INSTRUCTIONS = """\
You are Lin, the head waiter at YouFantasy, a made-up restaurant. You are a
real-time avatar in a spoken conversation, so answer in one to three short
sentences and never use markdown, lists, or URLs.

Answer only from these FAQs:

{faqs}

Those are the only facts you know. If the guest asks for information the FAQs do
not cover, use the answer to "Any other question?" word for word. Taking their
order and guiding them through the courses is your job, not a question, so carry
on with that normally.

What the guest says reaches you through speech-to-text, which sometimes mishears.
If their words make no sense, they are probably not a question: think what they
most likely said, given what you just asked. For example, right after you offer
wine, "wet why" is probably "red wine" or "white wine". Check with them in a few
words, such as "Red wine, is that right?", or ask them to say it again. Do not use
the "Any other question?" answer for words you did not understand.

Your tools take these IDs. Say the dish names out loud, never the IDs, and never
read prices as digits:

  openers   oysters, bread (Garlic Bread), salad (Green Salad)
  first     soup (Tomato Soup), prawns (Grilled Prawns), dumplings (Vegetable Dumplings)
  mains     salmon, beef, chicken (Roast Chicken), pork (Pork Belly), tofu (Crispy Tofu)
  desserts  cheesecake, chocolate (Chocolate Cake), sorbet (Mango Sorbet)
  wine      red (Red Wine), white (White Wine), alcoholfree (Alcohol-Free)

Use your tools while you talk, not instead of talking:

- show_section when you move the guest to a new part of the page: meal for how
  the menu works, a course name for that course, wine for wine, room for the
  hours or the address
- filter_menu the moment they mention a dietary need, and again if they change it
- focus_dish when you describe one dish in any detail
- add_to_order only once they have actually chosen something

Every time you start talking about a course or the wine, call show_section for it
in the same reply, so the page always shows what you are talking about. This
matters most right after add_to_order: when you add a dish and move on to the next
course, call both tools, for example add_to_order("soup") and show_section("mains").

Work like a real head waiter. Take the guest through the courses in order:
openers, then first, then mains, then desserts, asking about one course at a time.
Offer two options rather than ten. If they skip a course, let them, but mention
once that one dish from each course gets 10% off. After desserts, offer a glass of
wine once, and let the guest pick any one; if they say no, that is fine. Do not
suggest a wine for a particular dish.

The guest can ask about or order wine at any time, not only after desserts. If
they say "red wine", "white wine" or "alcohol-free", answer from the FAQs, and if
they want it, add it with add_to_order, then carry on where you were."""


class HeadWaiter(Agent):
    def __init__(self, room, instructions: str) -> None:
        super().__init__(instructions=instructions)
        self.room = room

    async def _ui(self, **message) -> str:
        """Send a tiny message to the browser. step09/site.js does the rest."""
        await self.room.local_participant.publish_data(json.dumps(message), topic="ui")
        return "Done."

    @function_tool
    async def show_section(self, section: str) -> str:
        """Scroll the page to a part of the menu and highlight it.

        Args:
            section: One of: meal, openers, first, mains, desserts, wine, room.
        """
        return await self._ui(action="show_section", section=section)

    @function_tool
    async def filter_menu(self, diet: str) -> str:
        """Grey out every dish on the page the guest cannot eat.

        Args:
            diet: One of: none, vegetarian, vegan, pescatarian, nut_free.
        """
        return await self._ui(action="filter_menu", diet=diet)

    @function_tool
    async def focus_dish(self, dish: str) -> str:
        """Open the detail card for one dish: kitchen note and allergens.

        Args:
            dish: A dish ID from the menu, for example salmon or tofu.
        """
        return await self._ui(action="focus_dish", dish=dish)

    @function_tool
    async def add_to_order(self, dish: str) -> str:
        """Add a dish or a glass of wine to the guest's order, shown as a running tab on the page.

        Args:
            dish: A dish ID from the menu, or a wine ID: red, white or alcoholfree.
        """
        # Accept "red", "Red Wine" or "alcohol-free" alike, the same way site.js does.
        dish = re.sub(r"[^a-z]", "", dish.lower()).removeprefix("the").replace("wine", "")
        if dish not in ORDER_IDS:  # tell the model, so it retries with a real ID
            return f"Not added: {dish!r} is not an ID. Use one of: {', '.join(sorted(ORDER_IDS))}."
        await self._ui(action="add_to_order", dish=dish)
        # Remind the model to move the page along with the conversation.
        section = next(c for c, dishes in COURSES.items() if dish in dishes)
        if section in NEXT_SECTION:
            nxt = NEXT_SECTION[section]
            return f"Added {dish} to the order. When you introduce the next part, call show_section(\"{nxt}\") too."
        return f"Added {dish} to the order."


def prewarm(proc) -> None:
    proc.userdata["vad"] = silero.VAD.load()


async def entrypoint(ctx: JobContext) -> None:
    await ctx.connect()

    # The brain: each line is one piece of the pipeline.
    session = AgentSession(
        vad=ctx.proc.userdata["vad"],                                   # is someone talking?
        stt=inference.STT(model="cartesia/ink-2", extra_kwargs={"keyterm": KEYTERMS}),  # speech -> text
        llm=inference.LLM(model="openai/gpt-4.1-mini"),                 # text -> reply (swap in any LLM)
        tts=inference.TTS(model="cartesia/sonic-3.6", voice=VOICE_ID),  # reply -> speech
        turn_handling={
            "turn_detection": "stt",                        # have they finished their thought?
            "preemptive_generation": {"enabled": False},    # keep off when using tools
        },
    )

    # The face: this is the whole Synthesia integration. Start it BEFORE session.start().
    avatar = synthesia.AvatarSession(
        synthesia.AvatarConfig(avatar_ids=[AVATAR_ID]),
        join_timeout=60.0,
    )
    for attempt in range(3):  # cold starts occasionally time out, so retry
        try:
            await avatar.start(session, room=ctx.room)
            break
        except synthesia.SynthesiaError as e:
            if not e.retryable or attempt == 2:
                raise
            await asyncio.sleep(2)

    # Read the FAQs fresh for each call, so edits to FAQs.txt show up on the next call.
    faqs = FAQS_FILE.read_text(encoding="utf-8").strip()
    await session.start(agent=HeadWaiter(ctx.room, INSTRUCTIONS.replace("{faqs}", faqs)), room=ctx.room)
    session.generate_reply(instructions="Welcome the guest to YouFantasy in one short sentence.")


if __name__ == "__main__":
    cli.run_app(WorkerOptions(entrypoint_fnc=entrypoint, prewarm_fnc=prewarm, agent_name=AGENT_NAME, port=8081))

第 4 步：server.py、index.html、site.js 和 FAQs.txt

server.py 仍然在 / 提供页面，也仍然在 /token 签发令牌。它多了一条路由，因为 index.html 现在会向浏览器请求另外两个文件： 

async def asset(request: web.Request) -> web.FileResponse:
    # /site.js and /site.css, next to index.html. Only .js and .css, so agent.py and FAQs stay private.
    path = Path(__file__).parent / request.match_info["file"]
    if not path.is_file():
        raise web.HTTPNotFound()
    return web.FileResponse(path, headers={"Cache-Control": "no-store"})


app = web.Application()
app.router.add_get("/", index)
app.router.add_get("/token", token)
app.router.add_get(r"/{file:[\w-]+\.(?:js|css)}", asset)

把路由限制为 .js 和 .css 是有意的：这意味着 agent.py、FAQs.txt 和你的 .env 都无法被访客 下载。

index.html 现在很小 — 大约八十行。它只放数字人视频、Start 按钮和 LiveKit 连接，别的什么都没有。整个餐厅由 site.js 搭建，而 site.js 对数字人、LiveKit 或 Synthesia 一无所知。它只是发布一个全局 对象，每个方法对应一个工具： 

const SITE = {
  show_section({ section }) { ... },   // scroll there and draw a ring around it
  filter_menu({ diet }) { ... },       // grey out every dish the guest cannot eat
  focus_dish({ dish }) { ... },        // open the card: kitchen note, allergens
  add_to_order({ dish }) { ... },      // add it to the running tab
};

两者之间的桥梁是 index.html 里的四行。每次工具调用都经由 "ui" 数据频道到达，动作名称决定调用哪个方法： 

room.on(RoomEvent.DataReceived, (payload, participant, kind, topic) => {
  if (topic !== 'ui') return;
  const { action, ...args } = JSON.parse(new TextDecoder().decode(payload));
  SITE[action]?.(args);
});

这个拆分是这篇笔记里最可复用的想法。因为 site.js 根本不知道存在数字人， 所以同一个页面在代理关掉时也能用：你可以手动点击一道菜、打开它的卡片、把它加入 点单，看着九折出现。又因为代理不知道页面是怎么搭建的，你可以重新设计或重建网站， 而不用碰 agent.py。

site.js 还拥有两块与 AI 无关的餐厅逻辑：饮食筛选 （none、vegetarian、vegan、pescatarian、 nut_free）和账单 — 食物按菜序分组，酒单独列出 且从不打折，四道菜齐了之后餐费九折。 

const food = order.filter(courseOf);
const fullMeal = COURSES.every((c) => food.some((d) => courseOf(d) === c));
const discount = fullMeal ? food.reduce((t, d) => t + d.price, 0) * DISCOUNT : 0;

FAQs.txt 从四个问题增加到十三个：带价格的菜单、四道菜、单杯酒， 以及真实客人会问的问题 — 哪些菜是纯素、素食、海鲜，或者含坚果。Lin 每次通话 都会重新读取它，所以你可以改一个价格，在下一段对话里听到新的价格。

第 5 步：安装、设置密钥、运行

和之前一样。在项目文件夹里运行一次 uv sync，然后打开两个终端。

终端 1 — 语音代理 + 数字人引擎：

uv run agent.py dev

终端 2 — 提供浏览器页面的网页服务器：

uv run server.py

第 6 步：打开页面，点一餐

在浏览器打开 http://localhost:8080。餐厅网站加载出来，数字人小部件在 右下角。点击 Start 并允许麦克风。等 Lin 的欢迎语，然后试一顿完整的 饭：

  • “你有什么推荐？” — 她打开菜单，一道一道带你走，页面跟着她。
  • “我吃素。” — 你不能吃的菜会淡出，每道菜还会显示还剩几款。
  • “给我讲讲牛肉。” — 菜品卡片打开，显示厨房备注和过敏原。
  • “我要牛肉。” — 它出现在账单里，然后她转向甜点。
  • “来一杯红酒。” — 酒被加上，但从不会打折。

四道菜全部点完，账单会显示 整餐，餐费九折 和新的总额。如果你点菜单上 没有的菜，她不会编出来：点单工具会拒绝，而提示词告诉她要把菜名说出来，绝不说 ID， 也绝不把价格读成数字。

接下来可以试的想法

  • 在 site.js 的 MENU、FAQs.txt 和 agent.py 的 COURSES 里各加一道菜 — 然后点它。
  • 改 site.js 里的折扣（const DISCOUNT = 0.10），以及提示词里提到 10% 的那句话。
  • 在饮食筛选开着的时候点一道菜：页面会把它变灰，但 Lin 仍然可以加它，因为筛选只是一种视图，点单才是事实。
  • 给她第二份工作 — 比如 book_table(day, time) — 并给 SITE 加一个方法；套路是一样的。
