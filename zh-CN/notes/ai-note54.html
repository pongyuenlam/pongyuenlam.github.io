如何把每一张人脸变成一串数字（人脸识别，版本 2）？

林邦源博士 · AI 笔记 · 2026 年 11 月 13 日 · 约 4 分钟阅读

版本 1 会显示照片，但对照片里的脸一无所知。版本 2 负责量度。它为每张照片找出人脸， 把那张脸描述成 128 个数字，然后把数字放进一个清单，把那个人的名字放进另一个清单。 这个版本还没有任何比较。这是让比较成为可能的那一步。

这些数字叫作人脸编码。它不是任何人读得懂的描述——不是"棕色眼睛、宽鼻子"—— 而是一组测量值，形式是电脑可以从另一组测量值里减掉的。同一个人的两张照片会给出两个 相近的清单。两个不同的人给出的清单会离得比较远。

为什么要用数字？

电脑没办法把两张脸当图片来比较。同一张脸的两张照片永远不会一模一样：光线变了， 头转了一点，摄像头的高度也不同。逐像素比较会说每一对都不一样。比较 128 个描述脸形的 测量值，就能抵住这些变化，并给出一个数字，说明两张脸差多少。版本 3 就是靠这个数字 判断谁是谁。

程序怎么运作

1. 加入人脸库

import face_recognition
import cv2
import os
import glob

face_recognition 是找出人脸、并把每张脸变成数字的库。另外三行跟版本 1 一样： cv2 读取图片，os 处理文件路径，glob 找出文件。

2. 找出照片

images_folder = "images"
images_path = glob.glob(os.path.join(images_folder, "*.*"))
print("{} images in folder".format(len(images_path)))

跟版本 1 一样，没有改动。打印出来的数目，仍然是确认文件夹找到了没有的最快办法。

3. 建两个空清单

known_face_encodings = []
known_face_names = []

一个清单放每个人的 128 个数字，另一个放对应的名字。顺序很重要：第一个清单第 0 位 放进去的东西，必须属于第二个清单第 0 位的名字。程序靠同一个循环里先加这个、再加那个， 来守住这个承诺。

4. 读取图片，修正颜色顺序

for img_path in images_path:
    img = cv2.imread(img_path)
    rgb_img = cv2.cvtColor(img, cv2.COLOR_BGR2RGB)
    basename = os.path.basename(img_path)
    (filename, ext) = os.path.splitext(basename)

cv2.imread 给出的是 BGR 顺序的像素格子：蓝、绿、红。 这是 OpenCV 的习惯，不是一般的顺序。face_recognition 要的是 RGB：红、绿、蓝。cv2.cvtColor 配上 cv2.COLOR_BGR2RGB，把第一个通道和最后一个通道对调，结果存进 rgb_img。

跳过这一行，程序不会崩。它会量错颜色，然后悄悄产出更差的编码——这种错只会在版本 3 冒出来，变成一张认不出的脸。所以这一行不能省。

最后两行还是版本 1 的：basename 去掉文件夹，splitext 把 Howard 和 .JPG 分开。

5. 量度人脸

    img_encoding = face_recognition.face_encodings(rgb_img)[0]

face_encodings 找出图片里的每一张脸，每张脸返回一个 128 个数字的清单。 最后那个 [0] 取第一个。

对一本护照式的照片文件夹来说，这样写是对的，因为每张照片里恰好只有一张清晰的脸。这也意味着 程序预期至少有一张脸：如果 face_encodings 一张都没找到，清单就是空的， [0] 会让程序报错停下。要改的是照片，不是代码——更清晰的图、更好的光， 或者更大的脸。

6. 把数字跟名字一起存起来

    known_face_encodings.append(img_encoding)
    known_face_names.append(filename)
    print("images encoded", filename)

append 加到每个清单的末尾，所以编码和名字始终对齐。print 显示进度，例如 images encoded Howard，每张照片一行。循环结束时，两个清单里 各有三个编码和三个名字，等着下一个版本用。

完整程序

把上面的片段拼回去，就是完整的文件，一共 18 行： 

import face_recognition
import cv2
import os
import glob
images_folder = "images"
images_path = glob.glob(os.path.join(images_folder, "*.*"))
print("{} images in folder".format(len(images_path)))
known_face_encodings = []
known_face_names = []
for img_path in images_path:
    img = cv2.imread(img_path)
    rgb_img = cv2.cvtColor(img, cv2.COLOR_BGR2RGB)
    basename = os.path.basename(img_path)
    (filename, ext) = os.path.splitext(basename)
    img_encoding = face_recognition.face_encodings(rgb_img)[0]
    known_face_encodings.append(img_encoding)
    known_face_names.append(filename)
    print("images encoded", filename)

亲眼看看这些数字

编码就是普通的 Python 清单，你可以看一个。在循环里、编码做好之后，加上这一行： 

    print(img_encoding)

画面会塞满 128 个小数，大约在 −0.15 到 0.15 之间。单独一个数字说明不了什么。 两个这样的清单并排放着，就能说明——那就是下一个版本要做的比较。

在自己的电脑上运行

用跟版本 1 一样的下载： 下载压缩包，解压， 用 Visual Studio Code 打开这个文件夹。这一篇用的是 face02.py。 第一次运行时，三行都跑： 

uv python pin 3.12.10
uv sync
uv run face02.py

这里慢的是 uv sync，因为 face_recognition 会带进 dlib 和 大约 100 MB 的模型。之后单独跑 uv run face02.py 就够了。

这三行只需要做一次。下次想再运行这个程序，只需输入 uv run face02.py。

每张照片只用一张清晰的脸，并用那个人的名字当文件名，例如 Anna.jpg。 如果一张照片上有两张脸，[0] 会悄悄取第一张，名字就会错，所以一个文件只放一个人。

下一步

版本 3 会把同一套量度指向一张新照片，把结果跟这些存下来的编码比较， 然后打印最接近的那个名字。
