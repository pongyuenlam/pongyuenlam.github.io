如何使用带天气工具的 LiveKit 语音代理（英文）？

林邦源 · AI 笔记 · 2026年11月4日 · 阅读时间约 6 分钟

语音代理（Voice Agent）是一种你可以实时对话的 AI 程序：你说话，它先把语音识别成文字（STT，speech-to-text），再把文字交给大语言模型（LLM），最后把答案转成语音播放给你听（TTS，text-to-speech）。LiveKit 是一个开源框架，把这三个部件通过网络串在一起，所以你的代理可以跑在服务器上，接受来自浏览器或电话的通话。

本笔记带你跑起一个精简但完整的语音代理 Python 程序。代理会先问候你、可以告诉你天气（示例工具）。

观看操作演示

在 Google Drive 打开 （无需账户）。

你需要准备什么

  • 一台 Mac（同样步骤也适用于 Windows 和 Linux）。
  • 已安装 Homebrew 以及 uv 包管理器——若尚未安装 uv，执行 brew install uv。
  • 一个 LiveKit Cloud 账号（免费的 Build 计划就够）。
  • LiveKit Cloud 的 API 凭证，复制到一个名为 .env 的文件——见下方步骤。

设置 LiveKit Cloud

到 cloud.livekit.io 注册账号。在控制台点 Projects → Create Project，打开项目后到 Keys 页面，复制三个值：

  • LIVEKIT_URL — 格式像 wss://your-project.livekit.cloud。
  • LIVEKIT_API_KEY — 短字符串，例如 APIxxxxxxxxxxxxx。
  • LIVEKIT_API_SECRET — 较长的字符串，只显示一次。

在你的项目文件夹里建立一个名为 .env 的文件，内容如下： 

LIVEKIT_URL=wss://your-project.livekit.cloud
LIVEKIT_API_KEY=APIxxxxxxxxxxxxx
LIVEKIT_API_SECRET=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

注意：千万不要把 .env 放上 GitHub 或任何公开网站——里面有真实凭证。

在自己电脑上运行

下载 zip 文件，解压到一个文件夹里。zip 里包含程序和 pyproject.toml 项目配置文件。把你的 .env 凭证文件放到同一文件夹（如上面「设置 LiveKit Cloud」步骤所示）。然后在 Visual Studio Code 里打开这个文件夹，在终端逐条输入以下两行： 

uv sync
uv run main.py console

uv sync 读取 pyproject.toml，如果你的电脑还没有 Python 3.13，它会自动下载安装，然后装好所有依赖包。uv run main.py console 会在终端启动代理，让你直接说话、并听到代理的回答。你只需要跑一次 uv sync——只有在修改了 main.py 或依赖包之后才需要重新跑。

程序文件

zip 里包含两个文件：pyproject.toml 和 main.py。下面是它们的完整内容供参考。

pyproject.toml

[project]
name = "folder-ai-livekit-agent"
version = "0.1.0"
requires-python = ">=3.13"
dependencies = [
    "livekit-agents>=1.8.4,<2",
    "python-dotenv",
    "requests",
]

[build-system]
requires = ["uv_build>=0.13.6,<0.14.0"]
build-backend = "uv_build"

main.py

import requests
from dotenv import load_dotenv
from livekit.agents import (
    Agent,
    AgentServer,
    AgentSession,
    JobContext,
    RunContext,
    cli,
    function_tool,
    inference,
)

load_dotenv()


def _geocode(city: str) -> tuple[float, float, str] | None:
    """Resolve a city name to (lat, lon, resolved_label) using Open-Meteo geocoding."""
    r = requests.get(
        "https://geocoding-api.open-meteo.com/v1/search",
        params={"name": city, "count": 1, "language": "en", "format": "json"},
        timeout=10,
    )
    results = r.json().get("results")
    if not results:
        return None
    best = results[0]
    name = best.get("name", city)
    country = best.get("country")
    label = f"{name}, {country}" if country else name
    return best["latitude"], best["longitude"], label


def _ip_location() -> tuple[float, float, str] | None:
    """Resolve lat/lon AND a human-readable city/region label from the caller's IP."""
    try:
        info = requests.get("https://ipinfo.io/json", timeout=10).json()
        lat_str, lon_str = info["loc"].split(",")
        parts = [p for p in (info.get("city"), info.get("region"), info.get("country")) if p]
        label = ", ".join(parts) if parts else "your current location"
        return float(lat_str), float(lon_str), label
    except Exception:
        return None


def _fetch_weather(latitude: float, longitude: float) -> dict:
    params = {
        "latitude": latitude,
        "longitude": longitude,
        "current": "temperature_2m,weather_code,relative_humidity_2m,apparent_temperature",
        "daily": "temperature_2m_max,temperature_2m_min,weather_code",
        "temperature_unit": "celsius",
        "timezone": "auto",
        "forecast_days": 1,
    }
    data = requests.get(
        "https://api.open-meteo.com/v1/forecast",
        params=params,
        timeout=10,
    ).json()
    return data


# WMO weather code -> short English description
_WMO_CODES = {
    0: "clear sky",
    1: "mainly clear", 2: "partly cloudy", 3: "overcast",
    45: "fog", 48: "freezing fog",
    51: "light drizzle", 53: "moderate drizzle", 55: "dense drizzle",
    56: "light freezing drizzle", 57: "dense freezing drizzle",
    61: "slight rain", 63: "moderate rain", 65: "heavy rain",
    66: "light freezing rain", 67: "heavy freezing rain",
    71: "slight snow fall", 73: "moderate snow fall", 75: "heavy snow fall",
    77: "snow grains",
    80: "slight rain showers", 81: "moderate rain showers", 82: "violent rain showers",
    85: "slight snow showers", 86: "heavy snow showers",
    95: "thunderstorm", 96: "thunderstorm with slight hail", 99: "thunderstorm with heavy hail",
}


@function_tool
async def lookup_weather(
    context: RunContext,
    location: str = "",
):
    """
    Look up weather information. If the user mentions a specific city or
    place (e.g. "Hong Kong", "Mountain View"), pass it in. Otherwise - when the
    user says "here", "my city", "where I am", or does not name any place -
    call this tool with no location argument. It will automatically detect
    the user's approximate city from their IP address.
    """

    lat = lon = None
    resolved = ""

    if location and location.strip():
        geo = _geocode(location.strip())
        if geo:
            lat, lon, resolved = geo

    if lat is None:
        ip = _ip_location()
        if ip is None:
            return {"error": "Could not detect your location automatically."}
        lat, lon, resolved = ip

    try:
        data = _fetch_weather(lat, lon)
    except Exception as e:
        return {"error": f"Weather service unavailable: {e}"}

    cur = data.get("current", {}) or {}
    daily = data.get("daily", {}) or {}
    code = cur.get("weather_code")
    condition = _WMO_CODES.get(code, f"code {code}") if code is not None else "unknown"

    return {
        "location": resolved,
        "temperature_c": cur.get("temperature_2m"),
        "feels_like_c": cur.get("apparent_temperature"),
        "condition": condition,
        "humidity_percent": cur.get("relative_humidity_2m"),
        "today_high_c": (daily.get("temperature_2m_max") or [None])[0],
        "today_low_c": (daily.get("temperature_2m_min") or [None])[0],
    }


server = AgentServer()


@server.rtc_session()
async def entrypoint(ctx: JobContext):
    session = AgentSession(
        vad=inference.VAD(),
        stt=inference.STT("deepgram/nova-3", language="multi"),
        llm=inference.LLM("google/gemma-4-31b-it"),
        tts=inference.TTS("cartesia/sonic-3", voice="9626c31c-bec5-4cca-baa8-f8ba9e84c8bc"),
    )

    agent = Agent(
        instructions=(
            "You are a friendly voice assistant built by LiveKit. "
            "You can answer weather questions. You do NOT need to ask the "
            "user which city they are in - if they do not name a specific "
            "city, just call lookup_weather() with no arguments and it will "
            "auto-detect their location. Only pass a location when the user "
            "explicitly names one (e.g. 'what's the weather in Hong Kong?'). "
            "Never ask 'which city?' - always try to answer directly first."
        ),
        tools=[lookup_weather],
    )

    await session.start(agent=agent, room=ctx.room)
    await session.generate_reply(instructions="greet the user and ask about their day")


if __name__ == "__main__":
    cli.run_app(server)

main.py 的运作原理（白话版）

语音活动检测、STT、LLM、TTS。AgentSession 这一行把四个组件串起来。 vad=inference.VAD() 是语音活动检测——它监听麦克风的音频流，告诉代理你何时开始和停止 说话，让 LLM 只处理真正的语音，而不是背景噪音。Deepgram（deepgram/nova-3）把语音 转成文字，Google Gemma 4（google/gemma-4-31b-it）回答文字内容，Cartesia （cartesia/sonic-3）把答案说出来。四者都在 LiveKit Cloud 上运行，所以不必向各供应商 分别申请 API key——一个 LiveKit 账户已涵盖它们。

真正的天气工具。lookup_weather 函数以 @function_tool 包装，告诉 LLM：「用户问天气时，你可以调用这个函数。」这个函数可以完整运行：它调用两个免费的 Open-Meteo 端点（一个把城市名称 转成经纬度，另一个获取实际天气预报）；若用户没有说出地点，就改用 ipinfo.io，从调用者的 IP 推测其大致 城市。它会返回温度（当前温度及今日最高／最低温，均以摄氏计）、体感温度、湿度、天气状况描述 （由 WMO 天气代码映射，例如 65 → "heavy rain"），以及解析后的城市名称。 如果任何 API 失败，它会返回 "error" 键，让 LLM 可以致歉，而不是编造数字。

提示词工程节省一次工具调用。代理指令刻意写得较长：「你不需要问用户在哪个城市—— 如果对方没有指明城市，就直接在不带参数的情况下调用 lookup_weather()，它会自动检测位置。 永远不要问『哪个城市？』——总是先尝试直接回答。」没有这段指示，LLM 往往会浪费一轮对话要求澄清， 听起来生硬，也拖慢对话。

亲切的问候。会话开始后， generate_reply(instructions="greet the user and ask about their day") 会让代理先说话， 所以来电者听到的是问候，而不是沉默。

跟你的代理对话

让 uv run main.py console 在终端执行中，程序会请求 Mac 的麦克风权限——按 Allow。然后对着麦克风说话：你应该会听到代理回你问候，接着就可以自由对话。想停止时按 Ctrl+C。

如果终端一直没反应，或显示缺少凭证的错误信息，按 Ctrl+C 停止，检查 .env 是否在项目文件夹，再执行一次 uv run main.py console。

局限

  • 你需要 LiveKit Cloud 账户，并在 .env 放入真实凭证。 没有它们程序不会启动。
  • 免费 Build 计划有上限（2026-11-04 查核）：每月 1,000 分钟会话、 $2.50 LiveKit Inference 额度（约 50 分钟通话）、冷启动——闲置一段时间后第一次通话可能 要等几秒才回应——以及只可部署一个代理。付费计划每月 $50 起。
  • 天气 API 免费但有限流。Open-Meteo 和 ipinfo.io 均供个人免费使用，但若 大量运行代理，可能需要付费方案或改用其他供应商。
