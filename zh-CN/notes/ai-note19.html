如何使用 LiveKit 语音代理？

林邦源 · AI 笔记 · 2026年11月4日 · 阅读时间约 6 分钟

语音代理（Voice Agent）是一种你可以实时对话的 AI 程序：你说话，它先把语音识别成文字（STT，speech-to-text），再把文字交给大语言模型（LLM），最后把答案转成语音播放给你听（TTS，text-to-speech）。LiveKit 是一个开源框架，把这三个部件通过网络串在一起，所以你的代理可以跑在服务器上，接受来自浏览器或电话的通话。

本笔记带你跑起一个精简但完整的语音代理 Python 程序。代理会先问候你、可以告诉你天气（示例工具），而且几分钟内就能部署到 LiveKit Cloud。你只需要在终端输入五条命令。

你需要准备什么

  • 一台 Mac（同样步骤也适用于 Windows 和 Linux）。
  • 已安装 Homebrew 以及 uv 包管理器——若尚未安装 uv，执行 brew install uv。
  • 一个 LiveKit Cloud 账号（免费的 Build 计划就够）。
  • LiveKit Cloud 的 API 凭证，复制到一个名为 .env 的文件——见下方步骤。

设置 LiveKit Cloud

到 cloud.livekit.io 注册账号。在控制台点 Projects → Create Project，打开项目后到 Keys 页面，复制三个值：

  • LIVEKIT_URL — 格式像 wss://your-project.livekit.cloud。
  • LIVEKIT_API_KEY — 短字符串，例如 APIxxxxxxxxxxxxx。
  • LIVEKIT_API_SECRET — 较长的字符串，只显示一次。

在你的项目文件夹里建立一个名为 .env 的文件，内容如下： 

LIVEKIT_URL=wss://your-project.livekit.cloud
LIVEKIT_API_KEY=APIxxxxxxxxxxxxx
LIVEKIT_API_SECRET=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

注意：千万不要把 .env 放上 GitHub 或任何公开网站——里面有真实凭证。

五条命令

打开终端，cd 进入你的项目文件夹，然后逐条执行以下五行。前两条告诉 uv 使用 Python 3.13；第三条初始化一个新项目；第四条安装 requirements.txt 列出的包；第五条启动代理。 

uv python install 3.13

下载 Python 3.13，并存进项目的 .venv 文件夹——不会动到 Mac 自带的 Python。

uv python pin 3.13

把这个项目锁定在 Python 3.13，让团队成员都用同一版本。

uv init

建立 pyproject.toml，这是 uv 管理项目的配置文件。

uv add -r requirements.txt

读取 requirements.txt，安装里面列出的所有包，包括 livekit-agents 和 python-dotenv。

uv run main.py

启动代理服务器，连上你的 LiveKit Cloud 项目。终端会显示类似 server running on localhost:7880 的信息。

两个 Python 文件

在执行上面的命令之前，先把以下两个文件粘贴进你的项目文件夹。

requirements.txt

livekit-agents>=1.8.4,<2
python-dotenv

main.py

from dotenv import load_dotenv
from livekit.agents import (
    Agent,
    AgentServer,
    AgentSession,
    JobContext,
    RunContext,
    cli,
    function_tool,
    inference,
)

load_dotenv()

@function_tool
async def lookup_weather(
    context: RunContext,
    location: str,
):
    """Used to look up weather information."""

    return {"weather": "sunny", "temperature": 70}


server = AgentServer()


@server.rtc_session()
async def entrypoint(ctx: JobContext):
    session = AgentSession(
        vad=inference.VAD(),
        stt=inference.STT("deepgram/nova-3", language="multi"),
        llm=inference.LLM("google/gemma-4-31b-it"),
        tts=inference.TTS("cartesia/sonic-3", voice="9626c31c-bec5-4cca-baa8-f8ba9e84c8bc"),
    )

    agent = Agent(
        instructions="You are a friendly voice assistant built by LiveKit.",
        tools=[lookup_weather],
    )

    await session.start(agent=agent, room=ctx.room)
    await session.generate_reply(instructions="greet the user and ask about their day")


if __name__ == "__main__":
    cli.run_app(server)

main.py 的运作原理（白话版）

STT、LLM、TTS。AgentSession 那行把三个部件串起来：Deepgram（deepgram/nova-3）把语音转文字，Google Gemma 4（google/gemma-4-31b-it）回答问题，Cartesia（cartesia/sonic-3）把答案念出来。三者都跑在 LiveKit Cloud 上，所以你不用分别向三家模型商申请 key——一个 LiveKit 账号就搞定。

工具函数。lookup_weather 函数前的 @function_tool 告诉 LLM：「用户问天气时可以调用这个函数」。目前它只会硬编码回答 "sunny", 70°F；真正的代理应该去调用 Open-Meteo 之类的天气 API。

主动问候。会话开始后，generate_reply(instructions="greet the user and ask about their day") 会让代理先说一句话，所以打电话进来的人听到的是问候，而不是沉默。

跟你的代理对话

让终端维持 uv run main.py 执行中，回到 LiveKit Cloud 控制台的 Rooms 页面，点 Create Room、输入一个名称、点 Join。新页面会显示这个房间的网址——把它复制到新浏览器标签，Mac 要求麦克风权限时按 Allow。说声 hello，代理应该会回你问候。

如果房间页面显示 「Agent not connected」，代表终端没在执行，或是 .env 里的凭证错了。按 Ctrl+C 停止服务器，检查 .env，然后再执行一次 uv run main.py。

局限

  • 需要 LiveKit Cloud 账号和正确的 .env 凭证。没有它们程序不会启动。
  • 免费 Build 计划的限制：每月 1,000 分钟通话、$2.50 LiveKit Inference 额度（约 50 分钟通话）、以及冷启动——闲置一阵子后第一次通话可能要等几秒才回应。付费计划每月 $50 起。
  • 示例天气工具是假的。永远回 sunny 和 70°F。要让代理能真正查天气，请改写成调用真实的 API。
