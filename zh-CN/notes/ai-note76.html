如何使用带天气工具的 LiveKit 语音代理（普通话）？

林邦源 · AI 笔记 · 2026年11月20日 · 阅读时间约 6 分钟

English 繁體中文 简体中文

如何使用带天气工具的 LiveKit 语音代理（英文）？ 建立一个用英语聆听、调用免费天气 API，并用声音回答的语音代理。本文是同一支程序，只有一个 区别：它用普通话聆听和回答。

这个区别听起来像翻译工作，其实小得多。整条管线——语音活动检测、语音识别、大型语言模型、 文字转语音——完全不变。需要改动的只有：交给识别器和发音器的语言、指令的措辞，以及天气 工具返回文字所用的语言。六处小改动就能全部完成。

普通话版本改了什么

  • 识别。由 language="multi" 改为 inference.STT("deepgram/nova-3", language="zh-CN")，让说出的普通话转成 中文字。
  • 发音。inference.TTS(..., language="zh") 告诉 Cartesia Sonic 3 文字是哪种语言，于是它说普通话而非英语。
  • 指令。代理被要求即使用户说英语或粤语，也要用普通话回答；示例问题 改为「香港天气怎么样？」。
  • 问候。generate_reply 收到中文指令，所以用户第一句 听到的就是普通话。
  • 地名。地理编码请求改用 language: "zh"，于是 「Hong Kong」会以 香港 返回。
  • 天气词汇。WMO 代码表改回中文描述，例如 65 → 大雨 而不是 "heavy rain"，模型就不必自行翻译工具结果。

其余一切——四模型管线、两个免费 API、.env 文件、两条终端命令——与英文版 完全相同。

你需要什么

  • 一台 Mac（同样步骤也适用于 Windows 和 Linux）。
  • 已安装 Homebrew 和 uv 包管理工具——若没有 uv，运行 brew install uv。
  • 一个 LiveKit Cloud 账户（免费 Build 计划已足够）。
  • 你的 LiveKit Cloud 凭证，复制到名为 .env 的文件——见下文。

设置 LiveKit Cloud

在 cloud.livekit.io 注册。在仪表板点击 Projects → Create Project，打开 该项目并前往 Keys，复制三个值：

  • LIVEKIT_URL — 形如 wss://your-project.livekit.cloud。
  • LIVEKIT_API_KEY — 短字符串，形如 APIxxxxxxxxxxxxx。
  • LIVEKIT_API_SECRET — 较长的字符串，只显示一次。

在项目文件夹中创建名为 .env 的文件，写入这三行： 

LIVEKIT_URL=wss://your-project.livekit.cloud
LIVEKIT_API_KEY=APIxxxxxxxxxxxxx
LIVEKIT_API_SECRET=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

重要：切勿把 .env 放到 GitHub 或任何公开网站——它包含你的真实凭证。

在自己的电脑上运行

下载 zip 文件，解压到 一个文件夹。zip 内有程序和 pyproject.toml 项目文件。加入你自己的 .env 文件（如上）。然后在 Visual Studio Code 打开该文件夹，在终端逐行输入： 

uv sync
uv run main.py console

uv sync 读取 pyproject.toml，若没有 Python 3.13 会先下载，然后 安装代理所需的所有包。接着 uv run main.py console 会在终端启动代理，让你 直接对它说话。uv sync 只需运行一次——之后只有改动 main.py 或 依赖项时才需要再运行。

Python 文件

zip 内有两个文件：pyproject.toml 和 main.py。以下列作参考。

pyproject.toml

[project]
name = "folder-ai-livekit-agent"
version = "0.1.0"
description = "LiveKit voice agent with a weather tool"
requires-python = ">=3.13"
dependencies = [
    "livekit-agents>=1.8.4,<2",
    "python-dotenv",
    "requests",
]

main.py

import requests
from dotenv import load_dotenv
from livekit.agents import (
    Agent,
    AgentServer,
    AgentSession,
    JobContext,
    RunContext,
    cli,
    function_tool,
    inference,
)

load_dotenv()


def _geocode(city: str) -> tuple[float, float, str] | None:
    """Resolve a city name to (lat, lon, resolved_label) using Open-Meteo geocoding."""
    r = requests.get(
        "https://geocoding-api.open-meteo.com/v1/search",
        params={"name": city, "count": 1, "language": "zh", "format": "json"},
        timeout=10,
    )
    results = r.json().get("results")
    if not results:
        return None
    best = results[0]
    name = best.get("name", city)
    country = best.get("country")
    label = f"{name}，{country}" if country else name
    return best["latitude"], best["longitude"], label


def _ip_location() -> tuple[float, float, str] | None:
    """Resolve lat/lon AND a human-readable city/region label from the caller's IP."""
    try:
        info = requests.get("https://ipinfo.io/json", timeout=10).json()
        lat_str, lon_str = info["loc"].split(",")
        parts = [p for p in (info.get("city"), info.get("region"), info.get("country")) if p]
        label = "，".join(parts) if parts else "你所在的位置"
        return float(lat_str), float(lon_str), label
    except Exception:
        return None


def _fetch_weather(latitude: float, longitude: float) -> dict:
    params = {
        "latitude": latitude,
        "longitude": longitude,
        "current": "temperature_2m,weather_code,relative_humidity_2m,apparent_temperature",
        "daily": "temperature_2m_max,temperature_2m_min,weather_code",
        "temperature_unit": "celsius",
        "timezone": "auto",
        "forecast_days": 1,
    }
    data = requests.get(
        "https://api.open-meteo.com/v1/forecast",
        params=params,
        timeout=10,
    ).json()
    return data


# WMO weather code -> short Chinese description
_WMO_CODES = {
    0: "晴空",
    1: "大致晴朗", 2: "部分多云", 3: "阴天",
    45: "雾", 48: "冻雾",
    51: "小毛毛雨", 53: "中等毛毛雨", 55: "大毛毛雨",
    56: "小冻毛毛雨", 57: "大冻毛毛雨",
    61: "小雨", 63: "中雨", 65: "大雨",
    66: "小冻雨", 67: "大冻雨",
    71: "小雪", 73: "中雪", 75: "大雪",
    77: "雪粒",
    80: "小阵雨", 81: "中阵雨", 82: "强阵雨",
    85: "小阵雪", 86: "大阵雪",
    95: "雷暴", 96: "雷暴伴小冰雹", 99: "雷暴伴大冰雹",
}


@function_tool
async def lookup_weather(
    context: RunContext,
    location: str = "",
):
    """
    Look up weather information. If the user mentions a specific city or
    place (e.g. "香港", "Hong Kong", "Mountain View"), pass it in. Otherwise —
    when the user says "这里", "我这边", "where I am", or does not name any
    place — call this tool with no location argument. It will automatically
    detect the user's approximate city from their IP address.
    """

    lat = lon = None
    resolved = ""

    if location and location.strip():
        geo = _geocode(location.strip())
        if geo:
            lat, lon, resolved = geo

    if lat is None:
        ip = _ip_location()
        if ip is None:
            return {"error": "无法自动判断你的位置。"}
        lat, lon, resolved = ip

    try:
        data = _fetch_weather(lat, lon)
    except Exception as e:
        return {"error": f"天气服务暂时不可用：{e}"}

    cur = data.get("current", {}) or {}
    daily = data.get("daily", {}) or {}
    code = cur.get("weather_code")
    condition = _WMO_CODES.get(code, f"代码 {code}") if code is not None else "未知"

    return {
        "location": resolved,
        "temperature_c": cur.get("temperature_2m"),
        "feels_like_c": cur.get("apparent_temperature"),
        "condition": condition,
        "humidity_percent": cur.get("relative_humidity_2m"),
        "today_high_c": (daily.get("temperature_2m_max") or [None])[0],
        "today_low_c": (daily.get("temperature_2m_min") or [None])[0],
    }


server = AgentServer()


@server.rtc_session()
async def entrypoint(ctx: JobContext):
    session = AgentSession(
        vad=inference.VAD(),
        # any combination of STT, LLM, TTS, or realtime API can be used
        # this example shows LiveKit Inference, a unified API to access different models via LiveKit Cloud
        # to use model provider keys directly, replace with the following:
        # from livekit.plugins import deepgram, openai, cartesia
        # stt=deepgram.STT(model="nova-3"),
        # llm=openai.LLM(model="gpt-4.1-mini"),
        # tts=cartesia.TTS(model="sonic-3", voice="9626c31c-bec5-4cca-baa8-f8ba9e84c8bc"),
        stt=inference.STT("deepgram/nova-3", language="zh-CN"),
        llm=inference.LLM("google/gemma-4-31b-it"),  # low-latency gemma, hosted on LiveKit
        tts=inference.TTS(
            "cartesia/sonic-3",
            voice="9626c31c-bec5-4cca-baa8-f8ba9e84c8bc",
            language="zh",
        ),
    )

    agent = Agent(
        instructions=(
            "You are a friendly voice assistant built by LiveKit. "
            "You always reply in Putonghua (Mandarin Chinese), in simplified "
            "characters, even when the user speaks English or Cantonese. "
            "You can answer weather questions. You do NOT need to ask the "
            "user which city they are in — if they do not name a specific "
            "city, just call lookup_weather() with no arguments and it will "
            "auto-detect their location. Only pass a location when the user "
            "explicitly names one (e.g. '香港天气怎么样？'). "
            "Never ask 'which city?' — always try to answer directly first. "
            "Keep answers short, because they will be spoken aloud."
        ),
        tools=[lookup_weather],
    )

    await session.start(agent=agent, room=ctx.room)
    await session.generate_reply(
        instructions="用普通话向用户打招呼，并问他今天过得怎么样。"
    )


if __name__ == "__main__":
    cli.run_app(server)

main.py 如何运作（用简单的话说）

同样的四个组件。AgentSession 仍然把语音活动检测、语音识别、 大型语言模型和文字转语音串在一起。识别器仍是 Deepgram Nova-3，声音仍是 Cartesia Sonic 3， 只是语言设置不同。Nova-3 接受 zh-CN，Sonic 3 接受 zh，LiveKit Inference 会把这些选择传下去，因此不需要另外申请各供应商的账户。

同一把声音，另一种语言。音色 ID 9626c31c-bec5-4cca-baa8-f8ba9e84c8bc 沿用英文版，所以代理听起来像同一位讲者， 只是改用普通话。Sonic 3 是多语言模型：同一个音色可以说它支持的任何语言。若你想要原生 普通话音色，把 ID 换成 Cartesia 音色库中的一个，并保留 language="zh" 即可。

指令仍然是方向盘。Agent(instructions=...) 内的段落现在写着 「always reply in Putonghua, in simplified characters, even when the user speaks English or Cantonese」。没有这一句，双语模型往往会跟随用户的语言，用英语回答。

工具也说中文。工具结果会原样送回模型，所以英文的 "heavy rain" 很容易在中文回答中重新出现为英文。工具内的两处改动——中文 WMO 描述和地理编码请求的 language: "zh"——让整个循环保持同一种语言。

普通话的亲切问候。会话开始后， generate_reply 收到指令「用普通话向用户打招呼，并问他今天过得怎么样。」， 所以用户听到的是普通话问候，而不是沉默。

与你的代理对话

在终端运行 uv run main.py console 后，程序会向你的 Mac 请求麦克风权限—— 点击 Allow。然后用普通话对麦克风说话：你应该听到代理用普通话回应，并可以 问某个城市的天气，例如「香港今天天气怎么样？」。想停止时按 Ctrl+C。

若按下播放后终端没有任何输出，或显示缺少凭证的错误，先停止服务器 （Ctrl+C），确认 .env 在项目文件夹内，再运行 uv run main.py console。

限制

  • 你需要 LiveKit Cloud 账户，并在 .env 放入真实凭证。 没有它们程序不会启动。
  • 免费 Build 计划有上限（2026-11-20 查核）：每月 1,000 分钟会话、 $2.50 LiveKit Inference 额度（约 50 分钟通话）、冷启动——闲置一段时间后第一次通话可能 要等几秒才回应——以及只可部署一个代理。付费计划每月 $50 起。
  • 声音是借来的。沿用英文音色 ID 会得到辨识度高、略带口音的普通话。这是 最小的改动，不是最好听的选择；换成 Cartesia 音色库的普通话音色只需改一行。
  • 天气 API 免费但有限流。Open-Meteo 和 ipinfo.io 对个人使用免费，但若 大量运行代理，可能需要付费方案或改用其他供应商。
