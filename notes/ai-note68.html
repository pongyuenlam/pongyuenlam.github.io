How to train your first forecasting model (Forecast, version 7)?

Howard Pong Yuen Lam · AI Notes · November 13, 2026 · 6 min read

English 繁體中文 简体中文

This is version 7 of the forecasting series, and the first version that actually learns. Versions 1 to 6 prepared the data: looked at it, cut it into windows, split each window into features and a target, and set aside a validation part. Version 7 adds a small network and runs it a hundred times over the training examples. Nothing about the model is clever; what this version teaches is the loop that turns a pile of examples into a trained model.

What the model is

The model takes the 29 recent days as input and gives back one number: its guess for the next day. Inside, it is a short chain of layers: 

nn.Linear(29, 10)  → ReLU
nn.Linear(10, 10)  → ReLU
nn.Linear(10, 1)

A Linear layer multiplies its inputs by a set of weights and adds a bias, so each of its outputs is a weighted sum of its inputs. The first layer turns 29 days into 10 numbers, the second turns those 10 into 10 more, and the last turns 10 into the single prediction.

ReLU sits between the layers and does something tiny: it replaces every negative number with zero and leaves positives alone. Without it the three Linear layers would collapse into one, and the model could only draw straight lines through the data. With it, the chain can bend.

How training works

One pass over the training examples is called an epoch. In each epoch the program does the same four things for every batch of 32 examples:

  1. Show the 29 days to the model and collect its guess.
  2. Compare the guess with the real next day, giving a loss.
  3. Work out which weights made the loss worse and by how much.
  4. Nudge every weight a little in the improving direction.

The loss here is mean squared error: subtract the guess from the answer, square it, and average over the batch. Squaring makes misses count more than near misses, and makes every error positive so that they add up instead of cancelling.

The nudging is done by the optimizer, here Adam with its default learning rate. It decides how big each nudge is. Version 9 will make that size a setting worth comparing; for now the default is kept.

After the training batches, the program measures the loss on the validation examples — the later days, which the model never learns from. Both numbers are recorded so they can be drawn.

How the program works

1. Define the network

class TimeSeriesModel(nn.Module):
    def __init__(self, window_size):
        super(TimeSeriesModel, self).__init__()
        self.network = nn.Sequential(
            nn.Linear(window_size-1, 10),  # window_size-1 because our features are window_size-1
            nn.ReLU(),
            nn.Linear(10, 10),
            nn.ReLU(),
            nn.Linear(10, 1)
        )

    def forward(self, x):
        return self.network(x)

class ... (nn.Module) is the standard way to define a PyTorch model. __init__ builds the layers once, and nn.Sequential means run these layers in this order. forward is what happens when the model is called: a batch goes in, a batch of predictions comes out. With window_size = 30, the first layer expects 29 numbers, which is exactly what the features hold.

2. Choose the loss and the optimizer

model = TimeSeriesModel(window_size)
criterion = nn.MSELoss()
optimizer = optim.Adam(model.parameters())

criterion is the measuring stick, mean squared error. optimizer is the hand that turns the dials; model.parameters() hands it every weight in the network, so it knows what it is allowed to change.

3. Pick where the work happens

num_epochs = 100
device = torch.device('cuda' if torch.cuda.is_available() else 'cpu')
model.to(device)

cuda is a graphics card that can do this arithmetic faster. On a Mac or on a laptop without one, the program quietly uses the cpu instead. model.to(device) moves the model to that place, and the batches will be moved to match.

4. The training loop

for epoch in range(num_epochs):
    model.train()
    train_loss = 0
    for batch_features, batch_targets in train_loader:
        batch_features = batch_features.to(device)
        batch_targets = batch_targets.to(device)
        outputs = model(batch_features)
        loss = criterion(outputs, batch_targets)
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()
        train_loss += loss.item()

model.train() puts the network in learning mode. The inner loop walks the training batches. For each one, model(batch_features) makes the guesses and criterion turns them into a loss.

The next three lines are the heart of the whole series. optimizer.zero_grad() clears the notes left over from the previous batch. loss.backward() works backwards through the network asking each weight how much did you contribute to this error? optimizer.step() then moves every weight a little, in the direction that lowers the error. Every learned model in this series is the result of repeating those three lines thousands of times.

5. Measure on the validation days

    model.eval()
    val_loss = 0
    with torch.no_grad():
        for batch_features, batch_targets in val_loader:
            batch_features = batch_features.to(device)
            batch_targets = batch_targets.to(device)
            outputs = model(batch_features)
            val_loss += criterion(outputs, batch_targets).item()

model.eval() switches to measuring mode, and torch.no_grad() says do not bother working out which weights are to blame, we are not changing them here. That saves time and memory. The validation loss is then divided by the number of batches so that training and validation losses are on the same scale, and the pair is printed every tenth epoch.

6. Draw two charts

plt.plot(train_losses, label='Training Loss')
plt.plot(val_losses, label='Validation Loss')

The first chart shows the two losses against epoch number: a line that should fall and then flatten. The second chart plots the model's guesses against the real validation days, grey for the truth and red for the prediction, so you can see whether the two lines sit on top of each other.

7. Reduce everything to one number

mae_torch = torch.mean(torch.abs(val_predictions_tensor - val_targets_tensor))
print(f"Validation MAE (PyTorch): {mae_torch:.4f}")

MAE, mean absolute error, is the average size of a miss, ignoring direction: in this run about 4.76. Since daily sales in the validation part run around HK$140, that is an average miss of roughly 3 per cent. MAE is easier to explain to a manager than the squared loss, which is why the program reports it alongside.

Your numbers will not match these exactly. The weights start at random values, so every run takes a slightly different path downhill. What should match is the shape: both losses fall quickly at first and then wobble around a similar level.

The two lines staying close is the healthy sign. If the training line kept falling while the validation line turned upward, the model would be memorising the training days instead of learning the pattern — a problem that later versions will make easier to spot.

The whole program

The pieces above, put back together. This is the complete file: 

import torch
from torch.utils.data import TensorDataset, DataLoader, Subset
import pandas as pd
import matplotlib.pyplot as plt
def create_sliding_windows_with_target(data, window_size, shift=1):
    windows = data.unfold(0, window_size, shift)
    features = windows[:, :-1]  # All columns except the last
    targets = windows[:, -1:]   # Just the last column
    return features, targets

df = pd.read_csv('time_series.csv')
series = df['series'].values
series_tensor = torch.tensor(series, dtype=torch.float32)
window_size = 30
features, targets = create_sliding_windows_with_target(series_tensor, window_size=window_size, shift=1)
full_dataset = TensorDataset(features, targets)

total_windows = len(full_dataset)
train_size = int(total_windows * 0.8)  # 80% for training, 20% for validation
train_indices = list(range(train_size))
val_indices = list(range(train_size, total_windows))

train_dataset = Subset(full_dataset, train_indices)
val_dataset = Subset(full_dataset, val_indices)

# Create DataLoaders
batch_size = 32
train_loader = DataLoader(train_dataset, batch_size=batch_size, shuffle=True)
val_loader = DataLoader(val_dataset, batch_size=batch_size, shuffle=False)

import torch
import torch.nn as nn
import torch.optim as optim

# Define the model
class TimeSeriesModel(nn.Module):
    def __init__(self, window_size):
        super(TimeSeriesModel, self).__init__()
        self.network = nn.Sequential(
            nn.Linear(window_size-1, 10),  # window_size-1 because our features are window_size-1
            nn.ReLU(),
            nn.Linear(10, 10),
            nn.ReLU(),
            nn.Linear(10, 1)
        )

    def forward(self, x):
        return self.network(x)

# Initialize model, loss function, and optimizer
model = TimeSeriesModel(window_size)
criterion = nn.MSELoss()
optimizer = optim.Adam(model.parameters())

# Training loop
num_epochs = 100
device = torch.device('cuda' if torch.cuda.is_available() else 'cpu')
model.to(device)

# Lists to store losses for plotting
train_losses = []
val_losses = []

for epoch in range(num_epochs):
    # Training phase
    model.train()
    train_loss = 0
    for batch_features, batch_targets in train_loader:
        batch_features = batch_features.to(device)
        batch_targets = batch_targets.to(device)

        # Forward pass
        outputs = model(batch_features)
        loss = criterion(outputs, batch_targets)

        # Backward pass and optimize
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()

        train_loss += loss.item()

    # Validation phase
    model.eval()
    val_loss = 0
    with torch.no_grad():
        for batch_features, batch_targets in val_loader:
            batch_features = batch_features.to(device)
            batch_targets = batch_targets.to(device)

            outputs = model(batch_features)
            val_loss += criterion(outputs, batch_targets).item()

    # Calculate average losses
    train_loss /= len(train_loader)
    val_loss /= len(val_loader)

    train_losses.append(train_loss)
    val_losses.append(val_loss)

    if (epoch + 1) % 10 == 0:
        print(f'Epoch [{epoch+1}/{num_epochs}], '
              f'Train Loss: {train_loss:.4f}, '
              f'Val Loss: {val_loss:.4f}')

# Plot training progress
plt.figure(figsize=(10, 6))
plt.plot(train_losses, label='Training Loss')
plt.plot(val_losses, label='Validation Loss')
plt.title('Model Loss Over Time')
plt.xlabel('Epoch')
plt.ylabel('Loss')
plt.legend()
plt.grid(True)
plt.show()

# Make predictions
model.eval()
with torch.no_grad():
    # Get predictions for validation set
    val_predictions = []
    val_targets = []
    for batch_features, batch_targets in val_loader:
        batch_features = batch_features.to(device)
        outputs = model(batch_features)
        val_predictions.extend(outputs.cpu().numpy())
        val_targets.extend(batch_targets.numpy())

# Plot predictions vs actual for validation set
plt.plot(val_targets, label='Actual', color="lightgrey")
plt.plot(val_predictions, label='Predicted', color="red")
plt.title('Predictions vs Actual Values (Validation Set)')
plt.xlabel('Time')
plt.ylabel('Value')
plt.legend()
plt.grid(True)
plt.show()

val_predictions_tensor = torch.tensor(val_predictions)
val_targets_tensor = torch.tensor(val_targets)
mae_torch = torch.mean(torch.abs(val_predictions_tensor - val_targets_tensor))
print(f"Validation MAE (PyTorch): {mae_torch:.4f}")

Running it on your own computer

Download the zip file and unzip it to a folder. The zip holds the programs in this series so far, the time_series.csv data file, and pyproject.toml. This note uses time_07.py. Open the folder in Visual Studio Code, then type these three lines in the terminal: 

uv python pin 3.12.10
uv sync
uv run time_07.py

The first line records which Python version this folder uses, and the second installs every package that pyproject.toml lists. The third line prints one line every ten epochs, then opens the loss chart and the prediction chart; close each window for the program to continue.

Those three lines are needed only once. The next time you want to run the program again, type just uv run time_07.py.

If you have not set up uv yet, start with How to install Visual Studio Code? and then the uv note for Windows or Mac.

What comes next

There is a model, but its quality is judged only on the validation days, and the validation days are the last 20 per cent of the data. Version 8 adds a third, untouched part — a test set — and reports four measures on it: MAE, MSE, RMSE and R².
