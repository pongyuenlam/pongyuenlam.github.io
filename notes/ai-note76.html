How to use LiveKit Voice Agent with Weather Tool (Putonghua)?

Howard Pong Yuen Lam · AI Notes · November 20, 2026 · 6 min read

How to use LiveKit Voice Agent with Weather Tool (English)? builds a voice agent that listens in English, calls a free weather API, and answers out loud. This note is the same program with one difference: it listens and answers in Putonghua.

That difference sounds like a translation job, but it is smaller than that. The pipeline — voice activity detection, speech recognition, the LLM, text-to-speech — is unchanged. Only the languages you hand to the recogniser and the speaker, the wording of the instructions, and the language of the words the weather tool returns need to move. Six small edits do all of it.

What changes for Putonghua

  • Recognition. inference.STT("deepgram/nova-3", language="zh-CN") instead of language="multi", so spoken Putonghua is transcribed as Chinese characters.
  • Speech. inference.TTS(..., language="zh") tells Cartesia Sonic 3 which language the text is in, so it speaks Putonghua instead of English.
  • Instructions. The agent is told to answer in Putonghua even when the caller speaks English or Cantonese, and the example question becomes “香港天气怎么样？”.
  • Greeting. generate_reply is given a Chinese instruction, so the first thing the caller hears is Putonghua.
  • Place names. The geocoding call asks Open-Meteo for language: "zh", so “Hong Kong” comes back as 香港.
  • Weather words. The WMO code table returns Chinese descriptions such as 65 → 大雨 rather than "heavy rain", so the model does not have to translate the tool result.

Everything else — the four-model pipeline, the two free APIs, the .env file, the two terminal commands — is exactly as in the English note.

What you need

  • A Mac (the same steps work on Windows and Linux too).
  • Homebrew installed and the uv package manager — if you do not have uv, run brew install uv.
  • A LiveKit Cloud account (the free Build plan is enough).
  • Your LiveKit Cloud credentials, which you copy into a file called .env — see below.

Set up LiveKit Cloud

Sign up at cloud.livekit.io. In the dashboard, click Projects → Create Project, then open the project and go to Keys. Copy the three values:

  • LIVEKIT_URL — looks like wss://your-project.livekit.cloud.
  • LIVEKIT_API_KEY — a short string like APIxxxxxxxxxxxxx.
  • LIVEKIT_API_SECRET — a longer string, shown only once.

In your project folder, create a file named .env with these three lines: 

LIVEKIT_URL=wss://your-project.livekit.cloud
LIVEKIT_API_KEY=APIxxxxxxxxxxxxx
LIVEKIT_API_SECRET=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

Important: never put .env on GitHub or any public site — it contains your live credentials.

Running it on your own computer

Download the zip file and unzip it to a folder. The zip holds the program and a pyproject.toml project file. Add your own .env file with the keys, as shown above. Then open the folder in Visual Studio Code and type these two lines in the terminal, one at a time: 

uv sync
uv run main.py console

uv sync reads pyproject.toml, downloads Python 3.13 if you do not already have it, and installs every package the agent needs. uv run main.py console then starts the agent in your Terminal so you can speak to it directly. You only need to run uv sync once — only re-run it if you later change main.py or the dependencies.

The Python files

The zip contains two files: pyproject.toml and main.py. Here they are for reference.

pyproject.toml

[project]
name = "folder-ai-livekit-agent"
version = "0.1.0"
description = "LiveKit voice agent with a weather tool"
requires-python = ">=3.13"
dependencies = [
    "livekit-agents>=1.8.4,<2",
    "python-dotenv",
    "requests",
]

main.py

import requests
from dotenv import load_dotenv
from livekit.agents import (
    Agent,
    AgentServer,
    AgentSession,
    JobContext,
    RunContext,
    cli,
    function_tool,
    inference,
)

load_dotenv()


def _geocode(city: str) -> tuple[float, float, str] | None:
    """Resolve a city name to (lat, lon, resolved_label) using Open-Meteo geocoding."""
    r = requests.get(
        "https://geocoding-api.open-meteo.com/v1/search",
        params={"name": city, "count": 1, "language": "zh", "format": "json"},
        timeout=10,
    )
    results = r.json().get("results")
    if not results:
        return None
    best = results[0]
    name = best.get("name", city)
    country = best.get("country")
    label = f"{name}，{country}" if country else name
    return best["latitude"], best["longitude"], label


def _ip_location() -> tuple[float, float, str] | None:
    """Resolve lat/lon AND a human-readable city/region label from the caller's IP."""
    try:
        info = requests.get("https://ipinfo.io/json", timeout=10).json()
        lat_str, lon_str = info["loc"].split(",")
        parts = [p for p in (info.get("city"), info.get("region"), info.get("country")) if p]
        label = "，".join(parts) if parts else "你所在的位置"
        return float(lat_str), float(lon_str), label
    except Exception:
        return None


def _fetch_weather(latitude: float, longitude: float) -> dict:
    params = {
        "latitude": latitude,
        "longitude": longitude,
        "current": "temperature_2m,weather_code,relative_humidity_2m,apparent_temperature",
        "daily": "temperature_2m_max,temperature_2m_min,weather_code",
        "temperature_unit": "celsius",
        "timezone": "auto",
        "forecast_days": 1,
    }
    data = requests.get(
        "https://api.open-meteo.com/v1/forecast",
        params=params,
        timeout=10,
    ).json()
    return data


# WMO weather code -> short Chinese description
_WMO_CODES = {
    0: "晴空",
    1: "大致晴朗", 2: "部分多云", 3: "阴天",
    45: "雾", 48: "冻雾",
    51: "小毛毛雨", 53: "中等毛毛雨", 55: "大毛毛雨",
    56: "小冻毛毛雨", 57: "大冻毛毛雨",
    61: "小雨", 63: "中雨", 65: "大雨",
    66: "小冻雨", 67: "大冻雨",
    71: "小雪", 73: "中雪", 75: "大雪",
    77: "雪粒",
    80: "小阵雨", 81: "中阵雨", 82: "强阵雨",
    85: "小阵雪", 86: "大阵雪",
    95: "雷暴", 96: "雷暴伴小冰雹", 99: "雷暴伴大冰雹",
}


@function_tool
async def lookup_weather(
    context: RunContext,
    location: str = "",
):
    """
    Look up weather information. If the user mentions a specific city or
    place (e.g. "香港", "Hong Kong", "Mountain View"), pass it in. Otherwise —
    when the user says "这里", "我这边", "where I am", or does not name any
    place — call this tool with no location argument. It will automatically
    detect the user's approximate city from their IP address.
    """

    lat = lon = None
    resolved = ""

    if location and location.strip():
        geo = _geocode(location.strip())
        if geo:
            lat, lon, resolved = geo

    if lat is None:
        ip = _ip_location()
        if ip is None:
            return {"error": "无法自动判断你的位置。"}
        lat, lon, resolved = ip

    try:
        data = _fetch_weather(lat, lon)
    except Exception as e:
        return {"error": f"天气服务暂时不可用：{e}"}

    cur = data.get("current", {}) or {}
    daily = data.get("daily", {}) or {}
    code = cur.get("weather_code")
    condition = _WMO_CODES.get(code, f"代码 {code}") if code is not None else "未知"

    return {
        "location": resolved,
        "temperature_c": cur.get("temperature_2m"),
        "feels_like_c": cur.get("apparent_temperature"),
        "condition": condition,
        "humidity_percent": cur.get("relative_humidity_2m"),
        "today_high_c": (daily.get("temperature_2m_max") or [None])[0],
        "today_low_c": (daily.get("temperature_2m_min") or [None])[0],
    }


server = AgentServer()


@server.rtc_session()
async def entrypoint(ctx: JobContext):
    session = AgentSession(
        vad=inference.VAD(),
        # any combination of STT, LLM, TTS, or realtime API can be used
        # this example shows LiveKit Inference, a unified API to access different models via LiveKit Cloud
        # to use model provider keys directly, replace with the following:
        # from livekit.plugins import deepgram, openai, cartesia
        # stt=deepgram.STT(model="nova-3"),
        # llm=openai.LLM(model="gpt-4.1-mini"),
        # tts=cartesia.TTS(model="sonic-3", voice="9626c31c-bec5-4cca-baa8-f8ba9e84c8bc"),
        stt=inference.STT("deepgram/nova-3", language="zh-CN"),
        llm=inference.LLM("google/gemma-4-31b-it"),  # low-latency gemma, hosted on LiveKit
        tts=inference.TTS(
            "cartesia/sonic-3",
            voice="9626c31c-bec5-4cca-baa8-f8ba9e84c8bc",
            language="zh",
        ),
    )

    agent = Agent(
        instructions=(
            "You are a friendly voice assistant built by LiveKit. "
            "You always reply in Putonghua (Mandarin Chinese), in simplified "
            "characters, even when the user speaks English or Cantonese. "
            "You can answer weather questions. You do NOT need to ask the "
            "user which city they are in — if they do not name a specific "
            "city, just call lookup_weather() with no arguments and it will "
            "auto-detect their location. Only pass a location when the user "
            "explicitly names one (e.g. '香港天气怎么样？'). "
            "Never ask 'which city?' — always try to answer directly first. "
            "Keep answers short, because they will be spoken aloud."
        ),
        tools=[lookup_weather],
    )

    await session.start(agent=agent, room=ctx.room)
    await session.generate_reply(
        instructions="用普通话向用户打招呼，并问他今天过得怎么样。"
    )


if __name__ == "__main__":
    cli.run_app(server)

How main.py works, in plain words

The same four pieces. AgentSession still wires together voice activity detection, speech recognition, the LLM and text-to-speech. The recogniser is still Deepgram Nova-3 and the voice is still Cartesia Sonic 3; only the language setting changes. Nova-3 accepts zh-CN and Sonic 3 accepts zh, and LiveKit Inference passes those choices through, so no separate provider accounts are needed.

One voice, another language. The voice ID 9626c31c-bec5-4cca-baa8-f8ba9e84c8bc is kept from the English note, so the agent sounds like the same speaker, now speaking Putonghua. Sonic 3 is multilingual: the same voice profile can speak any of its supported languages. If you want a native Putonghua voice instead, replace the ID with one from Cartesia’s voice library and leave language="zh" in place.

Instructions still do the steering. The paragraph inside Agent(instructions=...) now says “always reply in Putonghua, in simplified characters, even when the user speaks English or Cantonese”. Without that sentence a bilingual model often mirrors the caller’s language and answers in English.

The tool speaks Chinese too. A tool result is fed straight back to the model, so an English "heavy rain" tends to reappear in English inside a Chinese answer. The two edits in the tool — Chinese WMO descriptions and language: "zh" on the geocoding request — keep the whole loop in one language.

A friendly greeting, in Putonghua. After the session starts, generate_reply is given the instruction “用普通话向用户打招呼，并问他今天过得怎么样。”, so the caller hears a Putonghua hello instead of silence.

Talk to your agent

With uv run main.py console running in your Terminal, the program will ask your Mac for microphone permission — click Allow. Then speak Putonghua into your microphone: you should hear the agent greet you back in Putonghua, and you can ask about the weather in a city, for example “香港今天天气怎么样？”. Press Ctrl+C when you want to stop.

If the Terminal does not print anything after you press play, or it shows an error about missing credentials, stop the server (Ctrl+C), check that .env is in the project folder, and run uv run main.py console again.

Limitations

  • You need a LiveKit Cloud account and real credentials in .env. The program will not start without them.
  • The free Build plan has limits (checked 2026-11-20): 1,000 session minutes per month, a $2.50 LiveKit Inference credit (about 50 minutes of calls), cold starts — the first call after an idle period may take a few seconds to answer — and only one deployed agent. Paid plans start at $50/month.
  • The voice is borrowed. Keeping the English voice ID gives a recognisable, slightly accented Putonghua. It is the smallest possible change, not the best-sounding one; a Putonghua voice from Cartesia’s library is a one-line swap.
  • The weather APIs are free but rate-limited. Open-Meteo and ipinfo.io are both free for personal use, but if you run the agent heavily you may need a paid tier or a different provider.
