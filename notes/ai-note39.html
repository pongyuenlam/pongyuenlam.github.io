How does an AI agent research a question with web search?

Howard Pong Yuen Lam · AI Notes · November 9, 2026 · 5 min read

The previous note asked a model with no tools: “When did Mark launch Muse?” It thought carefully and answered, honestly, “I don't know.” This note asks the same question and adds one tool: a web search, provided by Tavily. The agent can now repeat the think → act → observe loop — up to five rounds — and stop only when it decides it knows the answer.

The script

This is ReAct03.py as it stands:

# Same ReAct idea as react01.py, but this task needs MORE THAN ONE action,
# so we repeat Think -> Act -> Observe in a loop until the model says "finish".
# Step 1: THINK  -> ask the model to reason about what to do next
# Step 2: ACT    -> ask for ONE action: search[...] or finish[...]
# Step 3: OBSERVE-> run the Tavily web search (a real tool), add the result to the prompt, loop again
import os
import re
from datetime import datetime
from tavily import TavilyClient
from openai import OpenAI
from dotenv import load_dotenv
load_dotenv()

client = OpenAI(
    api_key=os.environ.get('DEEPSEEK_API_KEY'),
    base_url="https://api.deepseek.com")
tavily = TavilyClient(api_key=os.environ.get('TAVILY_API_KEY'))

def ask(prompt, stop=None):
    """Send one prompt to the model and return its text reply."""
    response = client.chat.completions.create(
        model="deepseek-flash",
        messages=[{"role": "user", "content": prompt}],
        stop=stop,   # stop writing when this text appears
    )
    return response.choices[0].message.content

# The only tool (action) our agent can use
def search_tavily(query):
    """Return the top web results from Tavily (title, url, short content)."""
    results = tavily.search(query=query, max_results=3)["results"]
    if not results:
        return f"No web results found for '{query}'."
    return "\n".join(f"[{r['title']}] ({r['url']}) {r['content'][:400]}"
                     for r in results)

task = ("When did Mark launch Muse")

prompt = f"""Task: {task}
You can use ONE tool: search[query] searches the web (Tavily) and returns the top results.
Today is {datetime.now().strftime('%Y-%m-%d')}.
Work in steps. Each step has a Thought, an Action, and an Observation."""

for step in range(1, 6):          # at most 5 rounds, so it cannot loop forever
    # ---- Step 1: THINK (Reasoning) ----
    thought = ask(prompt + f"\n\nThought {step}: (reason briefly about what to do next; do not act yet)",
                  stop=["Action"])   # stop the model inventing its own Action/Observation
    print(f"=== Round {step} - Thought ===")
    print(thought)

    # ---- Step 2: ACT — append the reasoning trace, then ask for an action ----
    prompt = prompt + f"\n\nThought {step}: {thought}"
    action = ask(prompt + "\n\nWhat action should be taken based on that? "
                 "Reply with ONLY: search[query] or finish[answer]").strip()
    print(f"=== Round {step} - Action chosen by the model ===")
    print(action)

    if action.startswith("finish"):
        answer = re.search(r"finish\[(.*)\]", action, re.S)
        print("=== Final Answer ===")
        print(answer.group(1) if answer else action)
        break

    # ---- Step 3: OBSERVE — our Python code (not the model) runs the tool ----
    query = re.search(r"search\[(.*)\]", action, re.S)
    observation = search_tavily(query.group(1)) if query else "Invalid action."
    print(f"=== Round {step} - Observation from Tavily web search ===")
    print(observation)
    prompt = prompt + f"\nAction {step}: {action}\nObservation {step}: {observation}"
else:
    print("=== Stopped: no answer after 5 rounds ===")

What each part does

  • Two keys, two services. DeepSeek supplies the thinking; Tavily supplies the searching. Tavily is a search service built for agents: you send a query, it returns clean titles, links and short extracts — no web pages to scrape. It has a free tier for trying it out.
  • search_tavily(query) keeps only the top three results and the first 400 characters of each. An observation that filled the screen would drown the reasoning.
  • The prompt states the rules: one tool, written as search[query]; today's date, so “today” and “this year” mean something; and the step shape — Thought, Action, Observation.
  • The loop has a budget. range(1, 6) allows at most five rounds. If the model never says finish[...], the program stops and says so. An agent without a budget is a bill without a ceiling.
  • stop=["Action"] is the guard rail. Left alone, a chat model happily continues the pattern and invents its own Action and Observation — fake search results. The stop word cuts the reply after the Thought, so the real action and the real observation always come from your code, never from the model's imagination.
  • The prompt grows each round. Every Thought, Action and Observation is appended, so round 4 can see everything rounds 1–3 found. The prompt is the agent's memory.

Compare this with the no-tools answer from the previous note. The question was identical; what changed is that reasoning now has something to work with. The interesting reasoning happens in round 2: the model reads three results, spots that CNBC and TechCrunch disagree about the date, and writes a sharper query to settle it. That judgment call is the part no tool can do for it.

Running it on your own computer

Download the demo program (Folder-AI-ReAct03.zip). The zip holds three files: ReAct03.py (the script above), pyproject.toml (the package list) and README.md.

  1. Open the folder in Visual Studio Code.
  2. Create a file named .env in the folder with two lines: 
    DEEPSEEK_API_KEY=your-deepseek-key
TAVILY_API_KEY=your-tavily-key
    Get the first from the DeepSeek console and the second from Tavily; both have free starting credit.
  3. In the Terminal, run: 
    uv sync
uv run ReAct03.py
    uv sync is needed only the first time; it reads pyproject.toml and installs openai, tavily-python and python-dotenv into the project.

Why this run matters

  • The loop did real research. Not one search, but three: each round read what the last one found and chose a better query. The conflicting dates were noticed and resolved, not averaged.
  • The answer carries its evidence. Every claim in the final sentence can be traced back to a named source in an Observation — which is exactly what a memory-only answer cannot offer.
  • The budget kept it honest. Five rounds were available; four were needed. The model decided when to stop, and the program would have stopped it anyway.
  • Same question, three answers. With no tools: “I don't know.” With one tool used once: a single guess at the date. With a loop: a checked, sourced answer. That is the arc of this series.
