How to use LiveKit Voice Agent with Weather Tool (Cantonese)?

Howard Pong Yuen Lam · AI Notes · November 20, 2026 · 6 min read

How to use LiveKit Voice Agent with Weather Tool (English)? builds a voice agent that listens in English, calls a free weather API, and answers out loud. The Putonghua version changes the languages and keeps everything else. This note goes one step further: the agent listens and answers in Cantonese, and that forces one change the other two versions did not need — a different text-to-speech model.

Cantonese is not just Putonghua with different pronunciation. The written form differs too: “he is not here” is 他不在 in written Chinese but 佢唔喺度 in written Cantonese. A speech engine that only knows Mandarin will read Cantonese characters with Mandarin sounds, and the result is not Cantonese. So the voice has to be chosen with the language in mind.

What changes for Cantonese

  • Recognition. inference.STT("deepgram/nova-3", language="zh-HK") instead of language="multi". Nova-3 lists zh-HK among its languages, so spoken Cantonese is transcribed as Chinese characters.
  • Speech, a new model. Cartesia Sonic 3, used in the other two versions, lists zh but no yue, so it has no Cantonese voice. The session switches to inference.TTS("inworld/inworld-tts-2", voice="Ashley", language="yue"), which does.
  • Instructions. The agent is told to reply in Cantonese, in traditional characters, using spoken Cantonese wording rather than written Mandarin, even when the caller speaks English or Putonghua.
  • Greeting. generate_reply is given a Cantonese instruction, so the first thing the caller hears is Cantonese.
  • Place names. The geocoding call asks Open-Meteo for language: "zh", so “Hong Kong” comes back as 香港.
  • Weather words. The WMO code table returns Cantonese descriptions in traditional characters, such as 65 → 大雨 and 80 → 驟雨.

The pipeline is still the same four pieces — voice activity detection, speech recognition, the LLM, text-to-speech — and all of them still run on LiveKit Cloud, so no separate provider accounts are needed.

What you need

  • A Mac (the same steps work on Windows and Linux too).
  • Homebrew installed and the uv package manager — if you do not have uv, run brew install uv.
  • A LiveKit Cloud account (the free Build plan is enough).
  • Your LiveKit Cloud credentials, which you copy into a file called .env — see below.

Set up LiveKit Cloud

Sign up at cloud.livekit.io. In the dashboard, click Projects → Create Project, then open the project and go to Keys. Copy the three values:

  • LIVEKIT_URL — looks like wss://your-project.livekit.cloud.
  • LIVEKIT_API_KEY — a short string like APIxxxxxxxxxxxxx.
  • LIVEKIT_API_SECRET — a longer string, shown only once.

In your project folder, create a file named .env with these three lines: 

LIVEKIT_URL=wss://your-project.livekit.cloud
LIVEKIT_API_KEY=APIxxxxxxxxxxxxx
LIVEKIT_API_SECRET=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

Important: never put .env on GitHub or any public site — it contains your live credentials.

Running it on your own computer

Download the zip file and unzip it to a folder. The zip holds the program and a pyproject.toml project file. Add your own .env file with the keys, as shown above. Then open the folder in Visual Studio Code and type these two lines in the terminal, one at a time: 

uv sync
uv run main.py console

uv sync reads pyproject.toml, downloads Python 3.13 if you do not already have it, and installs every package the agent needs. uv run main.py console then starts the agent in your Terminal so you can speak to it directly. You only need to run uv sync once — only re-run it if you later change main.py or the dependencies.

The Python files

The zip contains two files: pyproject.toml and main.py. Here they are for reference.

pyproject.toml

[project]
name = "folder-ai-livekit-agent"
version = "0.1.0"
description = "LiveKit voice agent with a weather tool"
requires-python = ">=3.13"
dependencies = [
    "livekit-agents>=1.8.4,<2",
    "python-dotenv",
    "requests",
]

main.py

import requests
from dotenv import load_dotenv
from livekit.agents import (
    Agent,
    AgentServer,
    AgentSession,
    JobContext,
    RunContext,
    cli,
    function_tool,
    inference,
)

load_dotenv()


def _geocode(city: str) -> tuple[float, float, str] | None:
    """Resolve a city name to (lat, lon, resolved_label) using Open-Meteo geocoding."""
    r = requests.get(
        "https://geocoding-api.open-meteo.com/v1/search",
        params={"name": city, "count": 1, "language": "zh", "format": "json"},
        timeout=10,
    )
    results = r.json().get("results")
    if not results:
        return None
    best = results[0]
    name = best.get("name", city)
    country = best.get("country")
    label = f"{name}，{country}" if country else name
    return best["latitude"], best["longitude"], label


def _ip_location() -> tuple[float, float, str] | None:
    """Resolve lat/lon AND a human-readable city/region label from the caller's IP."""
    try:
        info = requests.get("https://ipinfo.io/json", timeout=10).json()
        lat_str, lon_str = info["loc"].split(",")
        parts = [p for p in (info.get("city"), info.get("region"), info.get("country")) if p]
        label = "，".join(parts) if parts else "你所在嘅位置"
        return float(lat_str), float(lon_str), label
    except Exception:
        return None


def _fetch_weather(latitude: float, longitude: float) -> dict:
    params = {
        "latitude": latitude,
        "longitude": longitude,
        "current": "temperature_2m,weather_code,relative_humidity_2m,apparent_temperature",
        "daily": "temperature_2m_max,temperature_2m_min,weather_code",
        "temperature_unit": "celsius",
        "timezone": "auto",
        "forecast_days": 1,
    }
    data = requests.get(
        "https://api.open-meteo.com/v1/forecast",
        params=params,
        timeout=10,
    ).json()
    return data


# WMO weather code -> short Cantonese description (traditional characters)
_WMO_CODES = {
    0: "天晴",
    1: "大致天晴", 2: "部分多雲", 3: "陰天",
    45: "有霧", 48: "凍霧",
    51: "微雨", 53: "細雨", 55: "密雨",
    56: "凍微雨", 57: "凍密雨",
    61: "小雨", 63: "中雨", 65: "大雨",
    66: "凍雨", 67: "大凍雨",
    71: "小雪", 73: "中雪", 75: "大雪",
    77: "雪粒",
    80: "驟雨", 81: "大驟雨", 82: "暴驟雨",
    85: "小陣雪", 86: "大陣雪",
    95: "雷暴", 96: "雷暴夾小冰雹", 99: "雷暴夾大冰雹",
}


@function_tool
async def lookup_weather(
    context: RunContext,
    location: str = "",
):
    """
    Look up weather information. If the user mentions a specific city or
    place (e.g. "香港", "Hong Kong", "Mountain View"), pass it in. Otherwise —
    when the user says "呢度", "我這邊", "where I am", or does not name any
    place — call this tool with no location argument. It will automatically
    detect the user's approximate city from their IP address.
    """

    lat = lon = None
    resolved = ""

    if location and location.strip():
        geo = _geocode(location.strip())
        if geo:
            lat, lon, resolved = geo

    if lat is None:
        ip = _ip_location()
        if ip is None:
            return {"error": "自動判斷唔到你嘅位置。"}
        lat, lon, resolved = ip

    try:
        data = _fetch_weather(lat, lon)
    except Exception as e:
        return {"error": f"天氣服務暫時用唔到：{e}"}

    cur = data.get("current", {}) or {}
    daily = data.get("daily", {}) or {}
    code = cur.get("weather_code")
    condition = _WMO_CODES.get(code, f"代碼 {code}") if code is not None else "未知"

    return {
        "location": resolved,
        "temperature_c": cur.get("temperature_2m"),
        "feels_like_c": cur.get("apparent_temperature"),
        "condition": condition,
        "humidity_percent": cur.get("relative_humidity_2m"),
        "today_high_c": (daily.get("temperature_2m_max") or [None])[0],
        "today_low_c": (daily.get("temperature_2m_min") or [None])[0],
    }


server = AgentServer()


@server.rtc_session()
async def entrypoint(ctx: JobContext):
    session = AgentSession(
        vad=inference.VAD(),
        # any combination of STT, LLM, TTS, or realtime API can be used
        # this example shows LiveKit Inference, a unified API to access different models via LiveKit Cloud
        # to use model provider keys directly, replace with the following:
        # from livekit.plugins import deepgram, openai, inworld
        # stt=deepgram.STT(model="nova-3"),
        # llm=openai.LLM(model="gpt-4.1-mini"),
        # tts=inworld.TTS(model="inworld-tts-2", voice="Ashley", language="yue"),
        stt=inference.STT("deepgram/nova-3", language="zh-HK"),
        llm=inference.LLM("google/gemma-4-31b-it"),  # low-latency gemma, hosted on LiveKit
        # Cartesia Sonic 3 has no Cantonese, so the voice comes from Inworld instead
        tts=inference.TTS(
            "inworld/inworld-tts-2",
            voice="Ashley",
            language="yue",
        ),
    )

    agent = Agent(
        instructions=(
            "You are a friendly voice assistant built by LiveKit. "
            "You always reply in Cantonese (廣東話), in traditional Chinese "
            "characters, even when the user speaks English or Putonghua. "
            "Use spoken Cantonese wording, not written Mandarin. "
            "You can answer weather questions. You do NOT need to ask the "
            "user which city they are in — if they do not name a specific "
            "city, just call lookup_weather() with no arguments and it will "
            "auto-detect their location. Only pass a location when the user "
            "explicitly names one (e.g. '香港今日天氣點呀？'). "
            "Never ask 'which city?' — always try to answer directly first. "
            "Keep answers short, because they will be spoken aloud."
        ),
        tools=[lookup_weather],
    )

    await session.start(agent=agent, room=ctx.room)
    await session.generate_reply(
        instructions="用廣東話同用戶打招呼，問佢今日過成點。"
    )


if __name__ == "__main__":
    cli.run_app(server)

How main.py works, in plain words

Recognition is a language code. inference.STT("deepgram/nova-3", language="zh-HK") tells Deepgram which Chinese to expect. zh-HK is the Hong Kong tag, and Nova-3 supports it alongside zh-CN, zh-TW and multi. Speaking Cantonese at a recogniser set to zh-CN produces characters that look plausible but often do not match what was said.

The voice had to move. Cartesia Sonic 3 is multilingual and covers Chinese, but its language list contains zh and no yue; there is no Cantonese voice to select. Inworld TTS 2.0 lists yue, so the session uses inference.TTS("inworld/inworld-tts-2", voice="Ashley", language="yue") instead. Everything else about the line is unchanged: model, voice and language are still passed to LiveKit Inference, and no Inworld account or key is needed.

The voice name is a starting point. Ashley is one of the sample voices LiveKit lists, and it is an English profile. It gives a recognisable Cantonese with a slight accent. Inworld publishes a larger voice library; copy the name of a Cantonese voice from Inworld’s TTS playground into the same voice= argument and nothing else changes.

Instructions still do the steering. The paragraph inside Agent(instructions=...) says “always reply in Cantonese, in traditional characters, using spoken Cantonese wording, not written Mandarin”. Without the last clause a bilingual model tends to answer in standard written Chinese, which reads correctly but sounds stiff when spoken.

The tool speaks Cantonese too. A tool result is fed straight back to the model, so an English "heavy rain" tends to reappear in English inside a Cantonese answer. The two edits in the tool — Cantonese WMO descriptions and language: "zh" on the geocoding request — keep the whole loop in one language.

A friendly greeting, in Cantonese. After the session starts, generate_reply is given the instruction “用廣東話同用戶打招呼，問佢今日過成點。”, so the caller hears a Cantonese hello instead of silence.

Talk to your agent

With uv run main.py console running in your Terminal, the program will ask your Mac for microphone permission — click Allow. Then speak Cantonese into your microphone: you should hear the agent greet you back in Cantonese, and you can ask about the weather in a city, for example “香港今日天氣點呀？”. Press Ctrl+C when you want to stop.

If the Terminal does not print anything after you press play, or it shows an error about missing credentials, stop the server (Ctrl+C), check that .env is in the project folder, and run uv run main.py console again.

Limitations

  • You need a LiveKit Cloud account and real credentials in .env. The program will not start without them.
  • The free Build plan has limits (checked 2026-11-20): 1,000 session minutes per month, a $2.50 LiveKit Inference credit (about 50 minutes of calls), cold starts — the first call after an idle period may take a few seconds to answer — and only one deployed agent. Paid plans start at $50/month.
  • The voice is a sample, not a native. Ashley is an English voice profile speaking Cantonese. It demonstrates the pipeline, but a Cantonese voice from Inworld’s library will sound far better, and the swap is one line.
  • Model coverage can change. Which providers offer Cantonese, and which language tags they accept, moves quickly. If yue is rejected, check the current language list on LiveKit’s TTS model pages before assuming the code is wrong.
  • The weather APIs are free but rate-limited. Open-Meteo and ipinfo.io are both free for personal use, but if you run the agent heavily you may need a paid tier or a different provider.
