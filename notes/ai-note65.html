How to split each window into features and a target (Forecast, version 4)?

Howard Pong Yuen Lam · AI Notes · November 13, 2026 · 5 min read

English 繁體中文 简体中文

This is version 4 of the forecasting series, and the last version before training begins. Version 4 cuts every window into two parts: the features, which are the days the model is allowed to look at, and the target, which is the day it must guess. It also switches from the ten toy numbers of version 2 to the real sales file, so the counts are now worth reading.

Features and target

Take one window of 30 days. The first 29 days are what the model will see; the 30th day is what it must predict. That single cut turns a window into one teachable example, and the words used for the two halves are worth remembering, because every later version uses them:

  • Features — the 29 known days. The input.
  • Target — the 30th day. The answer the model is graded against.

Because every window loses one number to the target, a window of 30 yields 29 features, not 30. That is where the number 29 comes from everywhere in this program.

How the program works

1. Import torch, its data tools, and pandas

import torch
from torch.utils.data import TensorDataset, DataLoader, Subset
import pandas as pd

TensorDataset pairs up features with targets so the two never drift apart. DataLoader serves those pairs to the model in batches. Subset is imported for the next version and is not used yet. pandas reads the CSV file, as in version 1.

2. Cut and split in one function

def create_sliding_windows_with_target(data, window_size, shift=1):
    windows = data.unfold(0, window_size, shift)
    row_n = windows.shape[0]
    col_n = windows.shape[1]
    features = windows[0:row_n, 0:col_n-1]  # All columns except the last
    targets = windows[0:row_n, col_n-1:col_n]   # Just the last column
    return features, targets

The first line is version 3's cutting, unchanged. windows.shape then reports the size of the result: row_n is how many windows there are, col_n is how long each one is.

The next two lines do the split. windows[0:row_n, 0:col_n-1] means every row, columns 0 up to but not including the last, which is the 29 known days. windows[0:row_n, col_n-1:col_n] means every row, the last column only, which is the answer. The comment on each line says the same thing in fewer words, and the last line returns both halves.

Note that the two slices do not overlap: no number is counted as both an input and an answer.

3. Load the real sales file

df = pd.read_csv('time_series.csv')
series = df['series'].values
series_tensor = torch.tensor(series, dtype=torch.float32)
window_size = 30

The first two lines bring in the 1,460 daily sales figures. The third line converts them from a plain array into a PyTorch tensor, the container the library calculates with, and dtype=torch.float32 makes each number a decimal rather than an integer — required, because sales figures have cents.

4. Build the dataset of examples

features, targets = create_sliding_windows_with_target(series_tensor, window_size=window_size, shift=1)
dataset = TensorDataset(features, targets)
batch_size = 32
train_loader = DataLoader(dataset, batch_size=batch_size, shuffle=True)

The first line calls the function and gets two lists back, the same length and in the same order: the first 29-day input belongs with the first answer, the second 29-day input with the second answer, and so on. TensorDataset glues each input to its own answer, so the two can never be separated by accident. DataLoader then hands the examples to the model 32 at a time instead of all 1,431 at once, and shuffle=True reshuffles the order before every pass. The reshuffling matters because the days arrive in date order; without it the model keeps seeing the same sequence and may learn a habit that comes from the order rather than from the sales themselves.

1,431 examples handed over 32 at a time makes 45 groups: 44 full ones and a last group holding the remaining 23.

5. Print what was built

print(f"Series length: {len(series)}")
print(f"Number of windows: {len(features)}")
print(f"Feature shape: {features.shape}")
print(f"Target shape: {targets.shape}")

These four lines are a habit worth copying: before training anything, print the shapes. If the numbers are wrong here, every result further down is wrong too, and finding that out now costs one run instead of an afternoon.

6. Peek at three examples

for i in range(3):
    print(f"\nWindow {i+1}:")
    print(f"Features (previous {window_size-1} days): {[f'{x:.2f}' for x in features[i].numpy()]}")
    print(f"Target (next day): {targets[i].item():.2f}")

The loop runs three times, once for each of the first three examples. Inside it, the first print labels the example, the second prints the 29 features rounded to two decimals, and the third prints the one target. The :.2f inside the braces means show two decimal places; without it the screen would fill with the full 17-digit version of every number.

What you should see

Series length: 1460
Number of windows: 1431
Feature shape: torch.Size([1431, 29])
Target shape: torch.Size([1431, 1])

First few windows:

Window 1:
Features (previous 29 days): ['29.40', '33.41', '37.86', ... '27.24', '28.71']
Target (next day): 27.08

Three numbers explain the whole output. The series has 1,460 days. A window of 30 over those 1,460 days has 1,460 − 30 + 1 = 1,431 possible starting positions, so there are 1,431 examples. The first starting position holds days 1 to 30, so it ends with day 30. The last starting position is 1,431: it holds days 1,431 to 1,460, so it ends with day 1,460, the final day in the file. Each example holds 29 inputs and 1 answer, which is why the two shapes are [1431, 29] and [1431, 1].

Look closely at the first example: the last feature is 28.71 and the target is 27.08. Then look at the second window in the full output. Its features begin where the first one ended, starting with 33.41, and its target is 39.27. That is exactly what a sliding window should do: shift by one day, keep the same 30 numbers, and let the earliest one fall away.

The whole program

The pieces above, put back together. This is the complete file, 27 lines in all: 

import torch
from torch.utils.data import TensorDataset, DataLoader, Subset
import pandas as pd
def create_sliding_windows_with_target(data, window_size, shift=1):
    windows = data.unfold(0, window_size, shift)
    row_n = windows.shape[0]
    col_n = windows.shape[1]
    features = windows[0:row_n, 0:col_n-1]  # All columns except the last
    targets = windows[0:row_n, col_n-1:col_n]   # Just the last column
    return features, targets
df = pd.read_csv('time_series.csv')
series = df['series'].values
series_tensor = torch.tensor(series, dtype=torch.float32)
window_size = 30
features, targets = create_sliding_windows_with_target(series_tensor, window_size=window_size, shift=1)
dataset = TensorDataset(features, targets)
batch_size = 32
train_loader = DataLoader(dataset, batch_size=batch_size, shuffle=True)
print(f"Series length: {len(series)}")
print(f"Number of windows: {len(features)}")
print(f"Feature shape: {features.shape}")  # Should be (num_windows, window_size-1)
print(f"Target shape: {targets.shape}")    # Should be (num_windows, 1)
print("\nFirst few windows:")
for i in range(3):
    print(f"\nWindow {i+1}:")
    print(f"Features (previous {window_size-1} days): {[f'{x:.2f}' for x in features[i].numpy()]}")
    print(f"Target (next day): {targets[i].item():.2f}")

Running it on your own computer

Download the zip file and unzip it to a folder. The zip holds the programs in this series so far, the time_series.csv data file, and pyproject.toml. This note uses time_04.py. Open the folder in Visual Studio Code, then type these three lines in the terminal: 

uv python pin 3.12.10
uv sync
uv run time_04.py

The first line records which Python version this folder uses, and the second installs every package that pyproject.toml lists. The third line prints the four counts and the three example windows in the terminal.

Those three lines are needed only once. The next time you want to run the program again, type just uv run time_04.py.

If you have not set up uv yet, start with How to install Visual Studio Code? and then the uv note for Windows or Mac.

What comes next

The dataset exists, but nothing has learned from it yet. Version 5 tidies the two slicing lines into a shorter form, and version 6 splits the examples into a training part and a validation part so that progress can be measured on days the model has not seen.
