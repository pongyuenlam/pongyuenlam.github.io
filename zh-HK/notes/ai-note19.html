如何使用 LiveKit 語音代理？

林邦源 · AI 筆記 · 2026年11月4日 · 閱讀時間約 6 分鐘

語音代理（Voice Agent）是一種你可以即時對話的 AI 程式：你說話，它先辨識你的語音轉成文字（STT，speech-to-text），再把文字交給大型語言模型（LLM），最後把答案轉回語音播放給你聽（TTS，text-to-speech）。LiveKit 是一個開源框架，把這三個部件透過網際網路串在一起，所以你的代理可以跑在伺服器上，接受來自瀏覽器或電話的通話。

本筆記带你跑起一個精簡但完整的語音代理 Python 程式。代理會先問候你、可以告訴你天氣（示範用工具），而且幾分鐘內就能部署到 LiveKit Cloud。你只需要在終端機輸入五條指令。

你需要準備什麼

  • 一部 Mac（同樣步驟也適用於 Windows 和 Linux）。
  • 已安裝 Homebrew 以及 uv 套件管理程式——若尚未安裝 uv，執行 brew install uv。
  • 一個 LiveKit Cloud 帳號（免費的 Build 計劃就夠）。
  • LiveKit Cloud 的 API 憑證，複製到一個名為 .env 的檔案——見下方步驟。

設定 LiveKit Cloud

到 cloud.livekit.io 註冊帳號。在控制台點 Projects → Create Project，打開專案後到 Keys 頁面，複製三個值：

  • LIVEKIT_URL — 格式像 wss://your-project.livekit.cloud。
  • LIVEKIT_API_KEY — 短字串，例如 APIpAmGzhYcWdi5。
  • LIVEKIT_API_SECRET — 較長的字串，只顯示一次。

在你的專案資料夾裡建立一個名為 .env 的檔案，內容如下： 

LIVEKIT_URL=wss://your-project.livekit.cloud
LIVEKIT_API_KEY=APIxxxxxxxxxxxxx
LIVEKIT_API_SECRET=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

注意：千萬不要把 .env 放上 GitHub 或任何公開網站——裡面有真實憑證。

五條指令

打開終端機，cd 進入你的專案資料夾，然後逐條執行以下五行。前兩條告訴 uv 使用 Python 3.13；第三條初始化一個新專案；第四條安裝 requirements.txt 列出的套件；第五條啟動代理。 

uv python install 3.13

下載 Python 3.13，並存進專案的 .venv 資料夾——不會動到 Mac 自帶的 Python。

uv python pin 3.13

把這個專案鎖定在 Python 3.13，讓團隊成員都用同一版本。

uv init

建立 pyproject.toml，這是 uv 管理專案的設定檔。

uv add -r requirements.txt

讀取 requirements.txt，安裝裡面列出的所有套件，包括 livekit-agents 和 python-dotenv。

uv run main.py

啟動代理伺服器，連上你的 LiveKit Cloud 專案。終端機會顯示類似 server running on localhost:7880 的訊息。

兩個 Python 檔案

在執行上面的指令之前，先把以下兩個檔案貼進你的專案資料夾。

requirements.txt

livekit-agents>=1.8.4,<2
python-dotenv

main.py

from dotenv import load_dotenv
from livekit.agents import (
    Agent,
    AgentServer,
    AgentSession,
    JobContext,
    RunContext,
    cli,
    function_tool,
    inference,
)

load_dotenv()

@function_tool
async def lookup_weather(
    context: RunContext,
    location: str,
):
    """Used to look up weather information."""

    return {"weather": "sunny", "temperature": 70}


server = AgentServer()


@server.rtc_session()
async def entrypoint(ctx: JobContext):
    session = AgentSession(
        vad=inference.VAD(),
        stt=inference.STT("deepgram/nova-3", language="multi"),
        llm=inference.LLM("google/gemma-4-31b-it"),
        tts=inference.TTS("cartesia/sonic-3", voice="9626c31c-bec5-4cca-baa8-f8ba9e84c8bc"),
    )

    agent = Agent(
        instructions="You are a friendly voice assistant built by LiveKit.",
        tools=[lookup_weather],
    )

    await session.start(agent=agent, room=ctx.room)
    await session.generate_reply(instructions="greet the user and ask about their day")


if __name__ == "__main__":
    cli.run_app(server)

main.py 的運作原理（白話版本）

STT、LLM、TTS。AgentSession 那行把三個部件串起來：Deepgram（deepgram/nova-3）把語音轉文字，Google Gemma 4（google/gemma-4-31b-it）回答問題，Cartesia（cartesia/sonic-3）把答案唸出來。三者都跑在 LiveKit Cloud 上，所以你不用分別向三家模型商申請 key——一個 LiveKit 帳號就搞定。

工具函式。lookup_weather 函式前的 @function_tool 告訴 LLM：「使用者問天氣時可以呼叫這個函式」。目前它只會硬編碼回答 "sunny", 70°F；真正的代理應該去呼叫 Open-Meteo 之類的天氣 API。

主動問候。會話開始後，generate_reply(instructions="greet the user and ask about their day") 會讓代理先說一句話，所以打電話進來的人聽到的是問候，而不是靜默。

跟你的代理對話

讓終端機維持 uv run main.py 執行中，回到 LiveKit Cloud 控制台的 Rooms 頁面，點 Create Room、輸入一個名稱、點 Join。新頁面會顯示這個房間的網址——把它複製到新瀏覽器分頁，Mac 要求麥克風權限時按 Allow。說聲 hello，代理應該會回你問候。

如果房間頁面顯示 「Agent not connected」，代表終端機沒在執行，或是 .env 裡的憑證錯了。按 Ctrl+C 停止伺服器，檢查 .env，然後再執行一次 uv run main.py。

局限

  • 需要 LiveKit Cloud 帳號和正確的 .env 憑證。沒有它們程式不會啟動。
  • 免費 Build 計劃的限制：每月 1,000 分鐘通話、$2.50 LiveKit Inference 額度（約 50 分鐘通話）、以及冷啟動——閒置一陣子後第一次通話可能要等幾秒才回應。付費計劃每月 $50 起。
  • 示範天氣工具是假的。永遠回 sunny 和 70°F。要讓代理能真正查天氣，請改寫成呼叫真實的 API。
