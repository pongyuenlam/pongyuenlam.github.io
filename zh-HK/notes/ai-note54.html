如何把每一張人臉變成一串數字（人臉辨識，版本 2）？

林邦源博士 · AI 筆記 · 2026 年 11 月 13 日 · 約 4 分鐘閱讀

版本 1 會顯示照片，但對照片裡的臉一無所知。版本 2 負責量度。它為每張照片找出人臉， 把那張臉描述成 128 個數字，然後把數字放進一個清單，把那個人的名字放進另一個清單。 這個版本還沒有任何比較。這是讓比較成為可能的那一步。

這些數字叫作人臉編碼。它不是任何人讀得懂的描述——不是"棕色眼睛、寬鼻子"—— 而是一組測量值，形式是電腦可以從另一組測量值裡減掉的。同一個人的兩張照片會給出兩個 相近的清單。兩個不同的人給出的清單會離得比較遠。

為什麼要用數字？

電腦沒辦法把兩張臉當圖片來比較。同一張臉的兩張照片永遠不會一模一樣：光線變了， 頭轉了一點，鏡頭的高度也不同。逐像素比較會說每一對都不一樣。比較 128 個描述臉形的 測量值，就能抵住這些變化，並給出一個數字，說明兩張臉差多少。版本 3 就是靠這個數字 判斷誰是誰。

程式怎麼運作

1. 加入人臉函式庫

import face_recognition
import cv2
import os
import glob

face_recognition 是找出人臉、並把每張臉變成數字的函式庫。另外三行跟版本 1 一樣： cv2 讀取圖片，os 處理檔案路徑，glob 找出檔案。

2. 找出照片

images_folder = "images"
images_path = glob.glob(os.path.join(images_folder, "*.*"))
print("{} images in folder".format(len(images_path)))

跟版本 1 一樣，沒有改動。印出來的數目，仍然是確認資料夾找到了沒有最快的方法。

3. 建兩個空清單

known_face_encodings = []
known_face_names = []

一個清單放每個人的 128 個數字，另一個放對應的名字。順序很重要：第一個清單第 0 位 放進去的東西，必須屬於第二個清單第 0 位的名字。程式靠同一個迴圈裡先加這個、再加那個， 來守住這個承諾。

4. 讀取圖片，修正顏色順序

for img_path in images_path:
    img = cv2.imread(img_path)
    rgb_img = cv2.cvtColor(img, cv2.COLOR_BGR2RGB)
    basename = os.path.basename(img_path)
    (filename, ext) = os.path.splitext(basename)

cv2.imread 給出的是 BGR 順序的像素格子：藍、綠、紅。 這是 OpenCV 的習慣，不是一般的順序。face_recognition 要的是 RGB：紅、綠、藍。cv2.cvtColor 配上 cv2.COLOR_BGR2RGB，把第一個通道和最後一個通道對調，結果存進 rgb_img。

跳過這一行，程式不會當掉。它會量錯顏色，然後悄悄產出更差的編碼——這種錯只會在版本 3 冒出來，變成一張認不出的臉。所以這一行不能省。

最後兩行還是版本 1 的：basename 去掉資料夾，splitext 把 Howard 和 .JPG 分開。

5. 量度人臉

    img_encoding = face_recognition.face_encodings(rgb_img)[0]

face_encodings 找出圖片裡的每一張臉，每張臉回傳一個 128 個數字的清單。 最後那個 [0] 取第一個。

對一本護照式的照片資料夾來說，這樣寫是對的，因為每張照片裡恰好只有一張清晰的臉。這也意味著 程式預期至少有一張臉：如果 face_encodings 一張都沒找到，清單就是空的， [0] 會讓程式報錯停下來。要改的是照片，不是程式碼——更清晰的圖、更好的光， 或者更大的臉。

6. 把數字跟名字一起存起來

    known_face_encodings.append(img_encoding)
    known_face_names.append(filename)
    print("images encoded", filename)

append 加到每個清單的末尾，所以編碼和名字始終對齊。print 顯示進度，例如 images encoded Howard，每張照片一行。迴圈結束時，兩個清單裡 各有三個編碼和三個名字，等著下一個版本用。

完整程式

把上面的片段拼回去，就是完整的檔案，一共 18 行： 

import face_recognition
import cv2
import os
import glob
images_folder = "images"
images_path = glob.glob(os.path.join(images_folder, "*.*"))
print("{} images in folder".format(len(images_path)))
known_face_encodings = []
known_face_names = []
for img_path in images_path:
    img = cv2.imread(img_path)
    rgb_img = cv2.cvtColor(img, cv2.COLOR_BGR2RGB)
    basename = os.path.basename(img_path)
    (filename, ext) = os.path.splitext(basename)
    img_encoding = face_recognition.face_encodings(rgb_img)[0]
    known_face_encodings.append(img_encoding)
    known_face_names.append(filename)
    print("images encoded", filename)

親眼看看這些數字

編碼就是普通的 Python 清單，你可以看一個。在迴圈裡、編碼做好之後，加上這一行： 

    print(img_encoding)

畫面會塞滿 128 個小數，大約在 −0.15 到 0.15 之間。單獨一個數字說明不了什麼。 兩個這樣的清單並排放著，就能說明——那就是下一個版本要做的比較。

在自己的電腦上執行

用跟版本 1 一樣的下載： 下載壓縮檔，解壓， 用 Visual Studio Code 打開這個資料夾。這一篇用的是 face02.py。 第一次執行時，三行都跑： 

uv python pin 3.12.10
uv sync
uv run face02.py

這裡慢的是 uv sync，因為 face_recognition 會帶進 dlib 和 大約 100 MB 的模型。之後單獨跑 uv run face02.py 就夠了。

這三行只需要做一次。下次想再執行這個程式，只需輸入 uv run face02.py。

每張照片只用一張清晰的臉，並用那個人的名字當檔名，例如 Anna.jpg。 如果一張照片上有兩張臉，[0] 會悄悄取第一張，名字就會錯，所以一個檔案只放一個人。

下一步

版本 3 會把同一套量度指向一張新照片，把結果跟這些存下來的編碼比較， 然後印出最接近的那個名字。
