如何把視窗長度變成一個設定（預測，版本 3）？

林邦源博士 · AI 筆記 · 2026 年 11 月 13 日 · 約 4 分鐘閱讀

這是預測系列的第 3 個版本。版本 2 用三個直接打在呼叫裡面的數字把數列切成視窗： unfold(0, 5, 1)。版本 3 把切割搬進一個函式，所以視窗大小 變成一個你可以在一個明顯的地方更改的設定。

為什麼要費事用函式？

函式是一段有名字、可以一次又一次呼叫的程式碼。把切割放進一個函式裡有兩種回報。第一， unfold 的三個參數現在有了你自己選的名字 —— data、 window_size、shift —— 它們說明了各自的意思。第二，較長的數列 變得容易嘗試：改一行，執行程式，整個輸出也隨之改變。

後面的版本會從一個訓練迴圈內部呼叫同一個函式，所以在這裡做的整理不只回報一次。

程式怎樣運作

1. 定義函式

import torch
def create_sliding_windows(data, window_size, shift):
    windows = data.unfold(0, window_size, shift)
    return windows

def 那一行把函式命名為 create_sliding_windows，並列出它需要 什麼：要切的數列、每一段的長度，以及每次要滑多遠。在裡面，unfold 接收 這三個值，而不是版本 2 那三個固定的 0, 5, 1。最後一行把結果交回， 所以呼叫這個函式的人可以用它。

定義一個函式並不會執行它。在檔案較下面呼叫這個函式之前，什麼都不會發生。

2. 建立一條較長的數列

data = torch.arange(1, 61)
window_size = 30

torch.arange(1, 61) 建立由 1 到 60 的整數。61 是停止點，Python 不包含它。 所以這條數列有 60 個值 —— 兩個月的每日銷售額。第二行把視窗長度陳述一次，放在一個名字 正好說明它是什麼的變數裡。

3. 呼叫函式

windows = create_sliding_windows(data, window_size, 1)

這一行才真正做工作。數列、視窗長度和步長被傳進去，片段在 windows 裡回來。 如果你想要長度為 10 的視窗，改上面 window_size 的值然後再執行檔案； 程式裡沒有其他東西需要移動。

4. 顯示每一個視窗

for window in windows:
    print(window.numpy())

迴圈和版本 2 一模一樣：一次取一個片段，各自印成普通陣列。改變了的是印出多少行。 用 60 個數字、視窗長度 30，有 60 − 30 + 1 = 31 個可能的起點，所以印出 31 個視窗， 如下所示。

完整程式

把上面的各部分放回一起。這就是完整的檔案，共 9 行： 

import torch
def create_sliding_windows(data, window_size, shift):
    windows = data.unfold(0, window_size, shift)
    return windows
data = torch.arange(1, 61)
window_size = 30
windows = create_sliding_windows(data, window_size, 1)
for window in windows:
    print(window.numpy())

在自己的電腦上執行

下載 zip 檔案並解壓到 一個資料夾。zip 裡有這個系列到目前為止的程式、time_series.csv 資料檔， 以及 pyproject.toml。這篇筆記用的是 time_03.py。在 Visual Studio Code 裡打開資料夾，然後在終端機輸入這三行： 

uv python pin 3.12.10
uv sync
uv run time_03.py

第一行記錄這個資料夾用哪個 Python 版本，第二行安裝 pyproject.toml 列出的 每一個套件。第三行在終端機印出 31 個視窗。

這三行只需要一次。下次想再執行程式，只打 uv run time_03.py。

如果你還沒有設定 uv，先看 如何安裝 Visual Studio Code？，然後看 uv 筆記的 Windows 或 Mac。

接下來是甚麼

視窗仍然只是一塊塊數字。程式裡沒有任何東西說明哪些數字是被給予的部分，哪一個是 答案。版本 4 把每個視窗拆成特徵與目標值，並把它們交給 PyTorch，成為一個模型可以學習的 資料集。
