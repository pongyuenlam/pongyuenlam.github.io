如何使用帶天氣工具的 LiveKit 語音代理（粵語）？

林邦源 · AI 筆記 · 2026年11月20日 · 閱讀時間約 6 分鐘

English 繁體中文 简体中文

如何使用帶天氣工具的 LiveKit 語音代理（英文）？ 建立一個用英語聆聽、呼叫免費天氣 API，並以聲音回答的語音代理。 普通話版本只改語言，其餘不變。本文再走一步：代理用 粵語聆聽與回答，而這迫使了一個前兩版都不需要的改動——更換文字轉語音模型。

粵語不只是讀音不同的普通話，書面形式也不同：「他不在」在書面中文是這樣寫，在書面粵語 則是「佢唔喺度」。只懂普通話的語音引擎會用普通話讀音去讀粵語字，結果並不是粵語。所以 聲音必須配合語言來選。

粵語版本改了甚麼

  • 辨識。由 language="multi" 改為 inference.STT("deepgram/nova-3", language="zh-HK")。Nova-3 的語言清單包含 zh-HK，說出的粵語會轉成中文字。
  • 發音，更換模型。前兩版使用的 Cartesia Sonic 3 只列出 zh， 沒有 yue，因此沒有粵語聲音。會話改用 inference.TTS("inworld/inworld-tts-2", voice="Ashley", language="yue")， 它支援粵語。
  • 指令。代理被要求用粵語、繁體字、口語化粵語措辭回答，而非書面普通話； 即使用戶說英語或普通話亦然。
  • 問候。generate_reply 收到粵語指令，使用者第一句聽到的 就是粵語。
  • 地名。地理編碼請求改用 language: "zh"，於是 「Hong Kong」會以 香港 回傳。
  • 天氣詞彙。WMO 代碼表回傳繁體粵語描述，例如 65 → 大雨、 80 → 驟雨。

管線仍是同樣四件組件——語音活動偵測、語音辨識、大型語言模型、文字轉語音——而且全部仍在 LiveKit Cloud 上執行，不需要另外申請各供應商的帳戶。

你需要甚麼

  • 一部 Mac（同樣步驟也適用於 Windows 與 Linux）。
  • 已安裝 Homebrew 與 uv 套件管理程式——若沒有 uv，執行 brew install uv。
  • 一個 LiveKit Cloud 帳戶（免費 Build 計劃已足夠）。
  • 你的 LiveKit Cloud 憑證，複製到名為 .env 的檔案——見下文。

設定 LiveKit Cloud

在 cloud.livekit.io 註冊。在儀表板按 Projects → Create Project，開啟 該專案並前往 Keys，複製三個值：

  • LIVEKIT_URL — 形如 wss://your-project.livekit.cloud。
  • LIVEKIT_API_KEY — 短字串，形如 APIxxxxxxxxxxxxx。
  • LIVEKIT_API_SECRET — 較長的字串，只顯示一次。

在專案資料夾中建立名為 .env 的檔案，寫入這三行： 

LIVEKIT_URL=wss://your-project.livekit.cloud
LIVEKIT_API_KEY=APIxxxxxxxxxxxxx
LIVEKIT_API_SECRET=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

重要：切勿把 .env 放上 GitHub 或任何公開網站——它包含你的實際憑證。

在自己的電腦上執行

下載 zip 檔案，解壓到 一個資料夾。zip 內有程式與 pyproject.toml 專案檔。加入你自己的 .env 檔案（如上）。然後在 Visual Studio Code 開啟該資料夾，在終端機逐行輸入： 

uv sync
uv run main.py console

uv sync 讀取 pyproject.toml，若沒有 Python 3.13 會先下載，然後 安裝代理所需的所有套件。接着 uv run main.py console 會在終端機啟動代理，讓你 直接對它說話。uv sync 只需執行一次——之後只有改動 main.py 或 相依套件時才需要再執行。

Python 檔案

zip 內有兩個檔案：pyproject.toml 與 main.py。以下列作參考。

pyproject.toml

[project]
name = "folder-ai-livekit-agent"
version = "0.1.0"
description = "LiveKit voice agent with a weather tool"
requires-python = ">=3.13"
dependencies = [
    "livekit-agents>=1.8.4,<2",
    "python-dotenv",
    "requests",
]

main.py

import requests
from dotenv import load_dotenv
from livekit.agents import (
    Agent,
    AgentServer,
    AgentSession,
    JobContext,
    RunContext,
    cli,
    function_tool,
    inference,
)

load_dotenv()


def _geocode(city: str) -> tuple[float, float, str] | None:
    """Resolve a city name to (lat, lon, resolved_label) using Open-Meteo geocoding."""
    r = requests.get(
        "https://geocoding-api.open-meteo.com/v1/search",
        params={"name": city, "count": 1, "language": "zh", "format": "json"},
        timeout=10,
    )
    results = r.json().get("results")
    if not results:
        return None
    best = results[0]
    name = best.get("name", city)
    country = best.get("country")
    label = f"{name}，{country}" if country else name
    return best["latitude"], best["longitude"], label


def _ip_location() -> tuple[float, float, str] | None:
    """Resolve lat/lon AND a human-readable city/region label from the caller's IP."""
    try:
        info = requests.get("https://ipinfo.io/json", timeout=10).json()
        lat_str, lon_str = info["loc"].split(",")
        parts = [p for p in (info.get("city"), info.get("region"), info.get("country")) if p]
        label = "，".join(parts) if parts else "你所在嘅位置"
        return float(lat_str), float(lon_str), label
    except Exception:
        return None


def _fetch_weather(latitude: float, longitude: float) -> dict:
    params = {
        "latitude": latitude,
        "longitude": longitude,
        "current": "temperature_2m,weather_code,relative_humidity_2m,apparent_temperature",
        "daily": "temperature_2m_max,temperature_2m_min,weather_code",
        "temperature_unit": "celsius",
        "timezone": "auto",
        "forecast_days": 1,
    }
    data = requests.get(
        "https://api.open-meteo.com/v1/forecast",
        params=params,
        timeout=10,
    ).json()
    return data


# WMO weather code -> short Cantonese description (traditional characters)
_WMO_CODES = {
    0: "天晴",
    1: "大致天晴", 2: "部分多雲", 3: "陰天",
    45: "有霧", 48: "凍霧",
    51: "微雨", 53: "細雨", 55: "密雨",
    56: "凍微雨", 57: "凍密雨",
    61: "小雨", 63: "中雨", 65: "大雨",
    66: "凍雨", 67: "大凍雨",
    71: "小雪", 73: "中雪", 75: "大雪",
    77: "雪粒",
    80: "驟雨", 81: "大驟雨", 82: "暴驟雨",
    85: "小陣雪", 86: "大陣雪",
    95: "雷暴", 96: "雷暴夾小冰雹", 99: "雷暴夾大冰雹",
}


@function_tool
async def lookup_weather(
    context: RunContext,
    location: str = "",
):
    """
    Look up weather information. If the user mentions a specific city or
    place (e.g. "香港", "Hong Kong", "Mountain View"), pass it in. Otherwise —
    when the user says "呢度", "我這邊", "where I am", or does not name any
    place — call this tool with no location argument. It will automatically
    detect the user's approximate city from their IP address.
    """

    lat = lon = None
    resolved = ""

    if location and location.strip():
        geo = _geocode(location.strip())
        if geo:
            lat, lon, resolved = geo

    if lat is None:
        ip = _ip_location()
        if ip is None:
            return {"error": "自動判斷唔到你嘅位置。"}
        lat, lon, resolved = ip

    try:
        data = _fetch_weather(lat, lon)
    except Exception as e:
        return {"error": f"天氣服務暫時用唔到：{e}"}

    cur = data.get("current", {}) or {}
    daily = data.get("daily", {}) or {}
    code = cur.get("weather_code")
    condition = _WMO_CODES.get(code, f"代碼 {code}") if code is not None else "未知"

    return {
        "location": resolved,
        "temperature_c": cur.get("temperature_2m"),
        "feels_like_c": cur.get("apparent_temperature"),
        "condition": condition,
        "humidity_percent": cur.get("relative_humidity_2m"),
        "today_high_c": (daily.get("temperature_2m_max") or [None])[0],
        "today_low_c": (daily.get("temperature_2m_min") or [None])[0],
    }


server = AgentServer()


@server.rtc_session()
async def entrypoint(ctx: JobContext):
    session = AgentSession(
        vad=inference.VAD(),
        # any combination of STT, LLM, TTS, or realtime API can be used
        # this example shows LiveKit Inference, a unified API to access different models via LiveKit Cloud
        # to use model provider keys directly, replace with the following:
        # from livekit.plugins import deepgram, openai, inworld
        # stt=deepgram.STT(model="nova-3"),
        # llm=openai.LLM(model="gpt-4.1-mini"),
        # tts=inworld.TTS(model="inworld-tts-2", voice="Ashley", language="yue"),
        stt=inference.STT("deepgram/nova-3", language="zh-HK"),
        llm=inference.LLM("google/gemma-4-31b-it"),  # low-latency gemma, hosted on LiveKit
        # Cartesia Sonic 3 has no Cantonese, so the voice comes from Inworld instead
        tts=inference.TTS(
            "inworld/inworld-tts-2",
            voice="Ashley",
            language="yue",
        ),
    )

    agent = Agent(
        instructions=(
            "You are a friendly voice assistant built by LiveKit. "
            "You always reply in Cantonese (廣東話), in traditional Chinese "
            "characters, even when the user speaks English or Putonghua. "
            "Use spoken Cantonese wording, not written Mandarin. "
            "You can answer weather questions. You do NOT need to ask the "
            "user which city they are in — if they do not name a specific "
            "city, just call lookup_weather() with no arguments and it will "
            "auto-detect their location. Only pass a location when the user "
            "explicitly names one (e.g. '香港今日天氣點呀？'). "
            "Never ask 'which city?' — always try to answer directly first. "
            "Keep answers short, because they will be spoken aloud."
        ),
        tools=[lookup_weather],
    )

    await session.start(agent=agent, room=ctx.room)
    await session.generate_reply(
        instructions="用廣東話同用戶打招呼，問佢今日過成點。"
    )


if __name__ == "__main__":
    cli.run_app(server)

main.py 如何運作（用簡單的話說）

辨識就是一個語言代碼。inference.STT("deepgram/nova-3", language="zh-HK") 告訴 Deepgram 預期哪一種中文。zh-HK 是香港標籤， Nova-3 與 zh-CN、zh-TW、multi 一樣支援它。對着設為 zh-CN 的辨識器說粵語，會得出看似合理但往往與你說的不符的字。

聲音必須更換。Cartesia Sonic 3 是多語言模型，涵蓋中文，但語言清單只有 zh，沒有 yue；沒有粵語聲音可選。Inworld TTS 2.0 列出 yue，所以會話改用 inference.TTS("inworld/inworld-tts-2", voice="Ashley", language="yue")。 其餘寫法不變：模型、音色與語言仍然交給 LiveKit Inference，不需要 Inworld 帳戶或金鑰。

音色名稱只是起點。Ashley 是 LiveKit 列出的示例音色之一，屬於 英語音色。它產生的粵語可辨，但略帶口音。Inworld 有更大的音色庫；把 Inworld TTS playground 中粵語音色的名稱複製到同一個 voice= 參數，其餘不用改。

指令仍然是方向盤。Agent(instructions=...) 內的段落寫着 「always reply in Cantonese, in traditional Chinese characters, using spoken Cantonese wording, not written Mandarin」。沒有最後一句，雙語模型往往用標準書面中文回答，看起來正確， 說出來卻生硬。

工具也說粵語。工具結果會原樣送回模型，所以英文的 "heavy rain" 很容易在粵語回答中重新出現為英文。工具內的兩處改動——粵語 WMO 描述與地理編碼請求的 language: "zh"——讓整個迴圈保持同一種語言。

粵語的親切問候。會話開始後， generate_reply 收到指令「用廣東話同用戶打招呼，問佢今日過成點。」， 所以使用者聽到的是粵語問候，而不是沉默。

與你的代理對話

在終端機執行 uv run main.py console 後，程式會向你的 Mac 要求麥克風權限—— 按 Allow。然後用粵語對麥克風說話：你應該聽到代理用粵語回應，並可以問 某個城市的天氣，例如「香港今日天氣點呀？」。想停止時按 Ctrl+C。

若按下播放後終端機沒有任何輸出，或顯示缺少憑證的錯誤，先停止伺服器 （Ctrl+C），確認 .env 在專案資料夾內，再執行 uv run main.py console。

限制

  • 你需要 LiveKit Cloud 帳戶，並在 .env 放入真實憑證。 沒有它們程式不會啟動。
  • 免費 Build 計劃有上限（2026-11-20 查核）：每月 1,000 分鐘會話、 $2.50 LiveKit Inference 額度（約 50 分鐘通話）、冷啟動——閒置一段時間後第一次通話可能 要等幾秒才回應——以及只可部署一個代理。付費計劃每月 $50 起。
  • 聲音是示例，不是母語者。Ashley 是英語音色說粵語。它示範 整條管線，但 Inworld 音色庫的粵語音色會好聽得多，而替換只需一行。
  • 模型覆蓋範圍會變。哪些供應商提供粵語、接受哪些語言標籤，變化很快。 若 yue 被拒絕，先查閱 LiveKit 最新的 TTS 模型語言清單，不要立刻假設程式 寫錯。
  • 天氣 API 免費但有限流。Open-Meteo 與 ipinfo.io 對個人使用免費，但若 大量執行代理，可能需要付費方案或改用其他供應商。
